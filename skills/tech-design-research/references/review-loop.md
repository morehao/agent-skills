# 独立评审 + 门禁闭环（review-loop）

本技能的验收段。定义、lens 追问、严重度分级**以 `tech-design/references/review-gate.md` 为唯一真源**，本文只给「带开源对标方案」这一路的取舍与串接顺序。

## 开工时先确认「评审做到哪一档」（选项式）

评审是有成本的（起 subagent、多轮改）。默认按档位跑，但**若用户对深度/时间有偏好，用选项问一次**：

- **完整评审**：跑全部相关 lens + builder check，改到 0 error/0 warn（完整档默认）。
- **标准评审（推荐）**：机械门禁 + 图校验 + 1–2 个关键 lens（按场景选），改到 0 error。
- **只跑机械门禁**：清占位符/空壳/缺图/DDL 不一致，不做语义 lens（赶时间时）。

用户没表态 → 标准档按「标准评审」、完整档按「完整评审」。**lens 数量与是否起 subagent 不省成「这次应该没问题」**——省可以，但要明说省了哪几个、风险是什么。

## 顺序：门禁 → 图校验 → lens → 收口 → 重跑门禁

### 1. 机械门禁（先清机械项）

```bash
node <tech-design>/scripts/check-design-doc.mjs <文档> --tier <light|standard|full> --strict
```

- `error` 必须清零；`warn` 要么改掉、要么在文档里写豁免理由（`--strict` 把 warn 当失败，本技能要求 0 warn）。
- 常见 warn 与修法：
  - `TD-DDL-MISMATCH`（附录 DDL 与正文字段表不一致）：**最容易在「按开源对标补了字段」后踩到**——补了 `domain` 表 DDL 就必须补对应的正文字段表。本次就靠它抓出漏。
  - `TD-NO-DIAGRAM` / `TD-DIAGRAM-MIN`：某节缺图或低于档位最小图集，补图或写 `图豁免：<理由>`。
  - `TD-SIZE`（超 ~20 屏）：note 级，单主题练习稿可接受，作为 note 说明理由保留。
- `note` 逐条确认已收口（`[待核实]`/`[假设]` 是否都在开放问题/假设节）。

### 2. 图校验

```bash
node <tech-design>/scripts/check-mermaid.mjs <生成的 .mmd 文件>   # 或内联块抽出来校验
node <tech-design>/scripts/audit-svg-topology.mjs <图.svg>...      # 结构类 SVG，端点须贴合
```

- `[MERMAID-ERROR]`、审计退出码非 0 → 必修。
- 自绘 SVG 要让节点带 `class="node"` 之类钩子，审计才能推断拓扑；否则会误判只识别到 1 个节点。

### 3. 独立评审（lens，独立上下文）

用 `subagent` 起 1–2 个 lens，**不要让作者自评**。按场景选：

| lens | 何时选 | 追问要点 |
| --- | --- | --- |
| 图与论证 | 含架构/流程/数据模型（标准档以上基本都要） | 每节该有的图在不在？图前导读/图后落着？时序覆盖异常/超时/降级分支？图里节点正文都有解释？有无同图双份？ |
| 数据与安全 | 动表结构 / 涉敏感数据 / 重定向类系统 | 每条索引回指查询？DDL 与正文逐项一致？状态机与字段语义一致？鉴权/越权？开放重定向/SSRF/DNS rebinding/IDN 闭合？日志脱敏与 UV 口径是否自洽？ |
| 调用方兼容 | 落点 B/C、改契约 | 谁在调（带证据）？行为变化清单？回归范围？ |
| 实施者视角（builder） | 完整档必跑 | 一个联系不上作者的人能否照排期？哪里必须猜且猜错改做法？ |

**subagent 契约**：只给文档路径 + 该 lens 追问清单（+ 必要时上游/代码路径），**不给作者的中间推理**；只回 `VERDICT` + top 3 findings（严重度/位置/改法）+ 报告路径，不把全文塞回父上下文。

### 4. 收口：单一裁决

合并所有 lens + 门禁，给**一个** `VERDICT: approve | revise`，findings 表：`ID | 严重度 | 位置 | 问题 | 改法 | 处置`。处置四选一：`autofix`（直接改）/ `discuss`（需拍板，进开放问题）/ `defer`（进开放问题并写触发条件）/ `ignore`（写理由）。

### 5. revise 的发现改完必须重跑门禁

改文档会引入新的机械问题（尤其补字段/补图之后）。**不重跑 = 没闭环**。

## 与「带开源对标」相关的特别检查

- 补进来的每个「业界做法」是否都写了取舍（代价 + 什么情况不选）？只写「业界这么做」不算。
- 参考资料对照表是否有**源码证据路径**（不是只有项目名）？
- 有没有把「不采纳的业界做法」也记下来（如 GeoIP 离线批处理）？

## 交付报告（贴原文，不写「应该没问题」）

给：文档路径 + 本次落点/场景/档位/专题 + **门禁原始末行** + **`VERDICT` 原文** + 图清单（共 N 张，各落哪节，SVG 给相对路径）+ 最需评审拍板的 1–2 点。没跑 gate 就写清为什么，不能写成「建议项，略过」。
