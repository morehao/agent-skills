# 输出落点 · 命名规则 · 收尾交付（delivery）

## 一、输出位置规则（探测环境 → 给选项让用户选）

**落点不自动定，先探测环境、再把候选路径做成选项让用户选。** 用户已明确指定路径时直接用，不再问。

### 1. 先探测环境（只读）

```bash
# 从当前目录逐级找最近的库根，然后从库根查看候选主题目录。
vault="$(pwd -P)"
while [ "$vault" != / ] && [ ! -d "$vault/.obsidian" ]; do
  vault="$(dirname "$vault")"
done
if [ -d "$vault/.obsidian" ]; then
  printf 'Obsidian 库根：%s\n' "$vault"
  ls -d "${vault%/}"/Learning/*/*/*/ 2>/dev/null | head  # 按实际库结构调整
fi
```

### 2. 构造选项（用 `ask_user_question` 让用户选一次）

按环境有无 Obsidian 决定选项集，**每个选项都要有推荐项（首项 + label 标「（推荐）」）**；**Obsidian 存在时推荐项就是库里最贴合的具体路径**，并直接列进选项，不要让用户自己去翻：

- **在 Obsidian 库内**（找到 `.obsidian`）→ 选项示例（把 `<主题目录>` 换成实际找到的路径，如 `Learning/Programming/架构与设计/系统设计实战/`）：
  1. **写入 Obsidian 库的 `<主题目录>/`（推荐）** —— 与同目录既有笔记同位置，有配套 MOC/清单可登记。
  2. Obsidian 库的其它目录 —— 让用户给路径（可自定义）。
  3. 写到当前工作区外的指定路径 —— 用户给绝对路径。
- **不在 Obsidian 库内** →
  1. 仓库既有 docs 约定（`docs/design/`、`docs/specs/`、`docs/rfc/`，取存在的那个）。
  2. 当前工作目录。
  3. 用户指定的其它路径。
- **已是明确的练习/单一库场景、且只有一个显然合适的目录**：仍给选项（至少两项：落该目录 / 自定义），但把最合适的放在第一并标注「推荐」。

> 选择「推荐」项后直接按第二节命名规则定文件名并写入；选「自定义」才追问具体路径。**没拿到用户选择就别写盘**（除非用户一开始就给了明确路径）。

### 3. 配套资产

SVG 图与文档**同目录**、英文语义名，正文相对路径引用；Mermaid 内联。过程物（调研台账 `-oss-source-review.md`、评审记录、备份）落 `.dsh/docs/notes/` 与 `.dsh/backups/`，默认 gitignore、不入库；要入库请显式指定 `docs/`。

## 二、命名规则

**技术设计文档一律 `<主题>-<类型>.md`**，不是「建议」是规则。

- **分隔符用连字符 `-`**：把「主题」和「类型」切开，零歧义、可扫读（一串中文名里连字符是唯一的断点视觉锚）、可扩展成组（`短链-系统设计`、`短链-压测方案`、`短链-部署手册` 天然同组）。
- **类型词取「系统设计」或「技术方案」**：这是技术方案，不是 UI 设计，**不要用「设计文档」**（易被读成交互/UI 设计）。
- **不要无分隔符连写**（`短链系统设计`）：中文分词有二义（`短链系统/设计` vs `短链/系统设计`），也不利于扩展成组。
- **裸主题名**（`短链.md`）只在「同目录全是裸名、且目录路径已表达分类」时 reluctantly 接受；追求清晰就用 `<主题>-<类型>`。

**定名前做两件事**：

1. **看同目录既有约定**：全是裸名 → 要么随大流、要么有理由地做唯一例外（说出来）。
2. **查撞名**：全库 `grep` 目标名与近似名（别处已有 `短链系统.md` 就别叫这个）。

**改名必须同步改链接**：

```bash
grep -rn "\[\[旧名\]\]\|\[\[旧名|" --include="*.md" .   # 查 wikilink
grep -rn "旧名\.md" --include="*.md" .                   # 查 Markdown 链接
mv "旧名.md" "新名.md"                                    # 改名（macOS 只改大小写需两步 mv）
# 逐处改链接，改完复查无残留：
grep -rn "\[\[旧名\]\]" --include="*.md" . || echo "无残留"
```

改完确认：新链接能解析（目标存在、路径对）、门禁仍通过。

## 三、交付清单与报告

- **文档路径** + 为什么落那儿（用户指定 > Obsidian 主题目录 > docs 约定 > 问用户）。
- **图资产**：SVG 同目录、英文语义名、相对路径引用。
- **过程物**：调研台账、评审 findings、备份。
- **交付报告**：路径 + 落点/场景/档位 + **门禁原始末行** + **`VERDICT` 原文** + 图清单（N 张，各落哪节）+ 最需拍板的 1–2 点。**不写「应该没问题」**。

## 四、备份（批量/结构改动前）

按本库约定：备份到 `.dsh/backups/<YYYYMMDD-HHMMSS>-<标签>/`，镜像目录结构并写 `manifest.json`（`created` / `op` / 涉及文件与 `sha256`）。改名、批量改字段表这类结构改动前先备份。

## 五、不做的事

- **不涉及任何 git 操作**（不 add / 不 commit / 不 push / 不建分支与 PR），也**不涉及技能发布**。
- 不自动打开文件（Web 环境无 `code` 语义）。
- 不把过程产物写进仓库正文目录。
