# Resume Griller（简历拷打 → 面试问题与答案键）

一份手册只回答三件事：**简历上写了什么**（可核验的事实）、**哪些地方必须当面问穿**（选题）、**听到什么才算过**（答案键与锚点）。其它内容一律删掉。

适用：用户是面试官或招聘方，手里有候选人简历，要一份能直接带进面试的材料。
不适用：帮候选人改简历 / 写简历 / 模拟面试陪练（求职者视角）、只有 JD 没有简历的通用题库、算法题与八股题库。

## 七条铁律

1. **每题必有题源**：每道题挂 `- 题源：「<简历原文>」— <项目/段落>`。引不出原文的题不出；想考的东西简历里没有，就写成「待核实项」放到面试前，不伪装成项目题。
2. **答案不替候选人编造**：示范答案分两层——简历可证的事实用「我们」，方案推演用「我会」；数字、职责、时间线、事故、评测集规模、机制细节都算事实，缺的写 `〔待补充：<要什么>〕` 或 `〔假设：<前提>〕`。**宁可标缺口，不要编一段看起来很顺的经历**。
3. **只问判断，不问复述**：好问题落在原则、取舍、失败归因、可证伪的评估、迁移推演；命令、参数、指标复述和实现细节不单独成题，除非它直接决定一个判断（判据见 [选题设计](references/question-design.md)）。
4. **覆盖度逐项交代**：简历「技能」栏里列出、但项目里没出现的技能，至少追一题核实；确实不问的写 `覆盖豁免：<理由>`。全表见手册的「覆盖核对」。
5. **时间预算是硬约束**：每题标分钟数与 `优先级：必问 / 选问 / 备用`，**必问 + 选问**的合计不得超过面试时长（备用不计）；「面试前」再给一行 `短版：40 分钟只问 Q1、Q3`。超了按优先级删题，不要压缩开场和收尾。
6. **评分靠锚点不靠印象**：维度分只按 [答案键与评分](references/answer-and-scoring.md) 的 4/3/2/1 锚点打，判定按固定优先级（1 → 2 → 均分）；★ 必须落在元数据 `level` 对应的档位（初级/中级标 3，高级/架构标 4），面评草稿必须能回指到具体哪一问的哪条记录。
7. **答案先保正确**：每条机制断言都要能说出成立条件，拿不准标 `〔待核实〕`；写完按 [答案正确性](references/accuracy.md) 的对照表与复核清单过一遍。**宁可少写一条机制，不要写一条错的。**

## 工作流（0 → 5）

### 0 收料

- 先写元数据块：`candidate` / `level` / `minutes` / `date` / `resume`。`level` 不是装饰——它决定 ★ 标在 3 还是 4，门禁会拿它和锚点对账。

- 输入：简历原文（粘贴文本 / `.md` / `.txt` / `.pdf` / `.docx` / 图片）、可选 JD、可选招聘方背景（团队在做什么、这个岗位要解决什么）、面试时长（默认 60 分钟）。
- 抽取：先试本机已有工具（`pdftotext <f> -`、`python3 -c "import pdfplumber"`、`office-docx` 技能），读不出就请用户粘贴正文。**不为抽取装依赖**；扫描件 / 图片简历用视觉读，并标明「按图片读取，可能有识别误差」，不得假装读到了 PDF 文本。
- 提问上限 3 个：缺简历正文、缺时长、缺岗位方向。其余按默认值执行，并在手册「注意事项」里写明假设（例：`未给 JD，按简历自述方向选题`）。
- 抽取后先落一份**清洗稿** `<slug>.resume.txt`：去掉 PDF 水印碎片与竖排噪声、合并断行。此后所有题源引用只对照这份清洗稿，不对照带噪声的原始抽取。
- 不复制、不提交候选人材料；产物默认写 `<cwd>/interview-<姓名拼音或首字母>-<YYYY-MM-DD>.md`，用户指定目录时以用户为准，**不写进仓库正文目录**。

### 1 取证

按 [手册格式契约](references/handbook-format.md) 的 facts 表逐项目过一遍：背景、本人角色、动作、结果、数字、疑点，每行带原文引用。
数字要有分母与口径（「QPS 从 200 到 2000」不等于「支撑 2000 QPS」）；「参与 / 负责 / 主导」要分清；时间线重叠、职级与职责不匹配、技能栏与项目不互证，都记成疑点，但**只记录，不在面试前下结论**。

### 2 选题

- 主题优先取**项目**（信息密度最高），其次取技能簇，最后才取协作与动机。**先出题池再挑题**：60 分钟出 10–14 道，其中「计划问」6–8 道（必问 3–4 + 选问 3–4），其余标 `备用`（二面、时间富余、想深挖时用）；30 分钟池 6–8、90 分钟池 14–18。
- 每个主题 1 个主问 + 0–3 个追问，追问写清「何时问」；不要为凑数把主问拆成两问。
- 按 [选题设计](references/question-design.md) 定深度与题型；同一技能不重复出题，换角度要说明新角度是什么。
- 出完填「覆盖核对」表：简历里的技能 / 项目逐项落到题号，或写 `覆盖豁免：<理由>`。

### 3 写答案键

每题四件套（写法见 [答案键与评分](references/answer-and-scoring.md)）：

- **要听的点**：4 / 3 / 2 / 1 四档锚点各一句，★ 标在及格线那一档（初级岗标 3，高级岗标 4）。
- **示范答案**：按**资深高级研发工程师**的水位写（给取舍、代价、失效条件、运维面），120–220 字，写成 **4–6 条缩进列表**——首条 `**结论**`、中间每条一个 `**加粗引导词**`、末条 `**核心原则**` 或 `**边界**`；内容仍按「结论 → 依据 → 取舍 → 边界」。简历可证的事实用「我们」，方案推演用「我会」；缺口写 `〔待补充：…〕`，前提写 `〔假设：…〕`。**不要堆成一大段**。
- **危险信号**：听到什么要停下来追问或扣分（含糊、甩锅、数字对不上、只讲团队不讲自己）。
- **优先级**：`必问` / `选问` / `备用`。预算只算必问与选问，备用题不占时间；备用也要写全答案键，面试官翻到就能用。

### 3.5 技术复核

写完答案键先别组装，按 [答案正确性](references/accuracy.md) 过一遍：高频错误对照表逐条扫，复核清单逐项勾。重点查三类——把「配置到位才成立」写成默认保证、把补偿说成回滚、替候选人编了没发生过的机制。有子 agent 时交独立上下文只回「哪条断言不成立、条件是什么」。

### 4 组装

按 [手册格式契约](references/handbook-format.md) 的骨架写：元数据块 → 面试前 → 面试（题）→ 覆盖核对 → 面试后。面试前只写面试官真会用的东西：一句话画像、必须核实的 2–3 件事（写清在哪一问核）、时间表、短版。

多份简历：**每人一份，不合并**，另加 `interview-index-<日期>.md` 列名单、岗位与各手册链接；不同候选人的题不要互相复制（会失去题源针对性）。

### 5 门禁与交付

```bash
node skills/resume-griller/scripts/check-interview-doc.mjs <手册.md> --strict
node skills/resume-griller/scripts/verify-sources.mjs <手册.md> --resume <slug>.resume.txt
```

`0 error / 0 warn`、且题源核验 0 条 `SRC-MISS` 才交付；`--list-rules` 查规则与严重度。门禁会核对 ★ 与 `level` 是否一致、时间表与每题时长是否对得上、围栏里的示例是否被误当题目——这三处都踩过坑。改文档而不是改门禁——门禁只判结构自洽，题目好不好归自检清单（[选题设计](references/question-design.md) 末节）。

交付时报告：题数与总时长、覆盖核对结论、仍未核实的疑点、门禁结果。**不替用户约面试、不生成候选人回复**。

## 红牌（出现这些念头就停下）

- 「简历写得挺好，直接按技能栏出几道」
- 「这题很有深度，虽然简历里没提」
- 「示范答案先写顺，数字与机制后面再说」
- 「答案写成一段更自然」
- 「这段机制读着顺，应该没错」
- 「追问放最后统一列一下」
- 「时间紧，覆盖核对先省了」
- 「评分表填个大概，反正面试官自己会判断」
- 「候选人材料先放进仓库，方便以后复用」

每一条的替代动作：无源不出题、缺口写 `〔待补充〕`/`〔假设〕`、追问贴回所属问题、覆盖逐项落题号、评分按锚点与 `level`、材料不落仓库。

## 已知边界

- **题源核验只判「在不在原文」**：`verify-sources.mjs` 能抓编造与改数字，抓不了「引文真、但标成项目经历、实际出自工作经历」——位置错要人读，危害也小（面试官当场看引文）。
- **覆盖核对的「虚标」判不了**：门禁只保证每个技能都落了题号，判不了「那道题是不是真在问它」（「分库分表」与「VDDS」词面对不上）。虚标靠评审与面试官自己核对。
- **规则数封顶**：31 条，按仓库准入规则不再为语义问题加规则；后续质量改进走 `references/question-design.md` 的自检清单与人工评审。
