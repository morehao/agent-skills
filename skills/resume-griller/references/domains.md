# 领域水位

「资深」是相对领域说的：电商交易的资深、直播社交的资深、IoT 云边的资深，关注的风险完全不同。**先判领域，再定水位**——通用后端答案（加缓存、加索引、加队列）在任何一个领域都不算资深。

## 先判领域

从三处取信号，命中即算，通常 1–3 个：

| 信号 | 例 |
|---|---|
| 公司/业务 | 微店（电商）、作业帮（在线教育）、麦可（直播社交）、云值守（IoT/云边） |
| 技术栈 | 秒杀/库存/对账 → 交易；WebSocket/房间/礼物 → 直播；MQTT/OTA/RTSP → IoT；向量检索/评测 → LLM 应用 |
| 简历里的结果 | 「TP99」「零超卖」「对账差异」「审核通过率」「门店在线率」 |

把判出来的领域写进手册「面试前」，并在注意事项里写「答案按 <领域> 资深水位写」。

## 各领域的资深关注点

| 领域 | 核心风险 | 必答机制 | 常见坑 |
|---|---|---|---|
| 电商交易 | 资损、超卖、履约超时 | 预占与对账、库存分层、幂等、活动风控 | 只谈 QPS 不谈少卖/超卖怎么赔 |
| 内容 / 直播社交 | 房间状态错乱、礼物计费、内容合规 | 房间权威源、消息序号、计费与风控、审核链路 | 只谈推送不谈掉线与计费 |
| 在线教育 | 课程名额、内容审核、版权 | 名额扣减、审核流、检索召回 | 只谈 CRUD 不谈审核与退款 |
| IoT / 云边 | 设备离线、OTA 变砖、视频隐私 | 设备身份、弱网重连、灰度与回滚、背压 | 只谈连接数不谈门店停机 |
| LLM 应用 | 幻觉、知识过期、成本、注入 | 评测集、拒答、知识时效、额度与限流 | 只谈「接了向量库」 |
| 支付 / 金融 | 重复扣款、对账差异、合规 | 幂等、状态机、对账、清结算 | 只谈接口联通不谈资损 |

## 写法

每条答案至少出现一个**该领域的后果**：钱、合规、门店能不能营业、学生能不能上课、商家敢不敢用。没有后果的答案，水位就是「通用后端」。

| 领域 | 通用答法 | 领域资深答法 |
|---|---|---|
| 电商 | 「加 Redis 缓存扛住峰值」 | 「超卖按订单赔付算资损，所以宁可少卖；卖出未成单要能自动退款」 |
| 直播 | 「用 WebSocket 推消息」 | 「麦位和礼物涉及计费，占位与消息都要能追溯到人，掉线不能还占着麦」 |
| IoT | 「MQTT 连上就行」 | 「升级失败会让门店停机，OTA 必须有灰度、校验与回滚窗口」 |
| LLM | 「接个向量库就不幻觉」 | 「错答会直接劝退商家，所以低置信要拒答转人工，评测集按真实问法标」 |

## 与「水位」的关系

`answer-and-scoring.md` 的「资深高级研发工程师」是**基线**，本文是**领域化**：基线决定「有没有取舍与边界」，领域决定「取舍该落在哪」。两者都过，答案才算合格。
