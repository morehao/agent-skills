# 多 agent 编排（可选）

题池 ≥10、领域 ≥2 时，单 agent 一次写十几道题容易**声音漂移**（同一份手册里有的题像资深、有的像背题）。这时可以拆给子 agent，但**按领域拆，不按题拆**。

## 分工

| 角色 | 负责 | 不负责 |
|---|---|---|
| 主 agent | 收料、facts 表、选题、题源引用、最终统一与门禁 | 不把答案键外包 |
| 领域子 agent（每领域 1 个） | 按同一 facts 表写该领域题目的答案键草稿，只回题目块 | 不新增题源、不改 4 档定义、不改格式 |
| 独立 reviewer（1 个） | 只回「哪条断言不成立、漏了什么条件」 | 不改写、不补题 |

## 约束

- 子 agent 必须拿到同一份 facts 表与同一份 [答案正确性](accuracy.md)，否则各写各的；
- 子 agent 只能引用手册里已有的题源，**不许自己从简历里另找句子**（避免引文张冠李戴）；
- 汇总由主 agent 做：统一「如果是我」口吻、统一 4–6 条分点、统一长度，再跑门禁与题源核验；
- 领域标注写进手册「面试前」，方便面试官判断哪几题该按哪个水位听。

## 成本与判断

- 3 个领域约等于 3 次并行起草 + 1 次独立复核，比单 agent 慢 20–40%，换来的是技术错误率下降；
- **不建议每个问题一个子 agent**：12 个子 agent 会带来上下文碎片、口径漂移、汇总成本高于收益，而且每道题都失去「同一场面试」的连贯性；
- 单领域、题池 <10 时，单 agent 写完再让一个 reviewer 复核就够了。
