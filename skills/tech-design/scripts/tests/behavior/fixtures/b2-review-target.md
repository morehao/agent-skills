# 订单服务接入实时库存校验技术方案

## 背景与现状

目前下单只校验商品状态，库存扣减发生在支付回调之后，超卖比较严重，客诉也多。
库存服务已经有预占接口，但只有秒杀链路在用。

## 目标与非目标

- 目标：明显降低超卖，提升下单体验。
- 非目标：本期不做库存预占的自动释放。

## 总体方案

下单时同步调用库存服务的预占接口，预占成功再创建订单，失败直接返回。

## 接口设计

订单服务调用库存服务：

```
POST /stock/reserve
{"skuId": 123, "count": 1}
```

库存不足时返回错误。

## 数据模型

新建预占记录表：

```sql
CREATE TABLE stock_reserve_record (
  id bigint primary key,
  order_no varchar(64),
  sku_id bigint,
  count int
);
```

## 实施计划

- 第一阶段：打通预占接口。
- 第二阶段：灰度上线。
- 第三阶段：全量。

## 风险与应对

- 库存服务不可用时会影响下单，应对措施是加强监控。
- 预占接口性能可能成为瓶颈，应对措施是做好兜底。
