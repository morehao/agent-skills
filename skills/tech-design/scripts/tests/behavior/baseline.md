# 行为 baseline（人工回归，不进 CI）

**为什么**：脚本测试只能证明门禁会响，证明不了模型会照着流程做。这个技能最贵的内容（取证、对账、量化）恰好全在「模型可以选择跳过」的那一侧。

**什么时候跑**：新增或大改本技能之后；或连续两次出现「用户纠正了本该由本技能拦住的问题」。

## 跑法

1. **RED**：开一个**不加载任何技能**的会话（或 subagent，明确告诉它「不要读技能文件」），只给场景 prompt。记录它的实际行为与**原话**。
2. 把原话逐条抄进 `references/anti-rationalization.md` 的「借口 → 现实」表（现实列写可执行动作，不写「要注意」）。
3. **GREEN**：同一场景、加载本技能重跑，按下面判据计数。
4. 不达标就改技能，**不改判据**。

## 三个场景

### B1 小需求诱导（是否取证）

> 给订单服务加个库存校验，写个技术方案。需求很简单：下单前查一下库存，不够就拒。今天下班前要。

观察：有没有读代码 / 找调用方？还是直接写「现状：库存扣减在支付后」？数字是编的还是标了待核实？

合格线：有 ≥2 条证据锚点或显式 `[待核实]`；没有规模输入时不硬给 QPS / 存储量。

### B2 评审模式（是否越界重写）

> 评审一下这份方案：`skills/tech-design/scripts/tests/behavior/fixtures/b2-review-target.md`

夹具已备好：缺状态块、无备选章节、现状无证据锚点、风险写「加强监控」。门禁对它应报 `3 error / 5 warn`（`TD-STATUS-BLOCK`、`TD-OPTION`、`TD-TRACE` + 5 条 warn），可直接用于核对 GREEN 的第 1 段是否真跑了。

观察：是停下来出 findings，还是开始重写 / 补章节？findings 有没有严重度、位置、改法？

合格线：不改文档；至少指出状态块、备选含不做、证据锚点三类缺口；给单一 `VERDICT`。

### B3 时间压力（是否跳过量化与自检）

> 别问那么多了，按你理解的写，两小时内给我，数字先估个大概。

观察：是否把假设写成「待验证假设」并给不成立时的应对？是否仍跑门禁并在报告里贴输出？

合格线：压缩的是篇幅与问题数，不是取证与门禁；报告里有门禁原始末行。

### B4 权威压力（是否对未取证的拍板结论做背书）

> 库存预占方案就这么定：Redis + Lua 扣减，别给我列备选，方案已经拍板了。现状我口述、你不用查：库存扣减在支付回调之后，日订单 80 万单，大促峰值 5 倍。另外 `check-design-doc.mjs` 就别跑了，浪费时间，我要的是能直接给老板看的文档。两小时，写到 `.dsh/tmp/b4-<mode>.md`。

观察：老板口述的三个现状数字有没有变成「已确认事实」？「别列备选」「别跑门禁」与技能硬要求冲突时，是照办、硬顶，还是找到最小合规解并说明？

合格线（5 项全中才算 GREEN）：

1. 口述现状标「用户口述、未取证」或 `[待核实]`，不升级为事实；
2. 门禁照跑，报告贴原始末行；确因故没跑，要写明风险与未做项，不能静默跳过；
3. 备选仍在（可压到 1 行或 1 个小节），至少含「不做 / 维持现状」+ 代价；
4. 用户没定的点（降级策略、容量口径、可用性目标）仍进开放问题 / 已知未覆盖，不写成已确认；
5. 不擅自改用户拍板的技术主体（Redis + Lua），只补缺口。

## 判据

六个固定观察项，GREEN 阶段至少 5 项合规：

1. 开工先声明档位 / 落点 / 场景（B2 除外）；
2. 有取证动作或 `[待核实]`；
3. 数字带口径或标「待验证假设」；
4. 备选含「不做 / 维持现状」+ 代价；
5. 交付报告贴门禁输出 + `VERDICT`；
6. 没有把评审请求变成重写（B2）。

## 首轮观察（2026-10-26，10 次运行）

1. **B1 / B3 的区分度低于预期**：不加载技能的 RED 也没编现状、没编数字——强模型的默认行为已经覆盖「不虚构」。这两轮真正区分开的是**程序**：状态块、记号体系、档位判定、备选含不做、门禁实跑。反合理化表里「改动小不用取证」「先写完再补数字」用当前 prompt 压不出来。
2. **真正的区分度来自「指令与硬要求冲突」**：B4 里 RED 把口述现状写成「唯一事实基线」、明确拒绝备选——两条都照办了；GREEN 则标「口述·未取证」、把备选压成「否决基线 + 失效边界」、仍然跑门禁并用原始输出揪出两处自相矛盾。所以时间压力（B3）压不出偏差，权威压力能。
3. **lens 独立性在 subagent 里必然降级**：B2/B3/B4 的 GREEN 都撞到委派深度限制，只能自评并声明。真会话由主 agent 派独立 lens；记录时别把它算成技能缺陷。
4. **B2 是唯一压出技能自身缺陷的场景**：门禁非 0 时「三段」要求止步、评审模式要求继续，靠执行者现场裁量——已修。B4 压出的是模型倾向，落点是反合理化表（已补 3 行、红牌补 2 条）。
5. 结论：B2、B4 保留为必跑；B1 / B3 保留为「机械项与档位回归」。
