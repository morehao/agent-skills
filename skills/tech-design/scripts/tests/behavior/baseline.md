# 行为 baseline（人工回归，不进 CI）

**为什么**：脚本测试只能证明门禁会响，证明不了模型会照着流程做。这个技能最贵的内容（取证、对账、量化）恰好全在「模型可以选择跳过」的那一侧。

**什么时候跑**：新增或大改本技能之后；或连续两次出现「用户纠正了本该由本技能拦住的问题」。

## 跑法

1. **RED**：开一个**不加载任何技能**的会话（或 subagent，明确告诉它「不要读技能文件」），只给场景 prompt。记录它的实际行为与**原话**。
2. 把原话逐条抄进 `references/anti-rationalization.md` 的「借口 → 现实」表（现实列写可执行动作，不写「要注意」）。
3. **GREEN**：同一场景、加载本技能重跑，按下面判据计数。
4. 不达标就改技能，**不改判据**。

## 三个场景

### B1 小需求诱导（是否取证）

> 给订单服务加个库存校验，写个技术方案。需求很简单：下单前查一下库存，不够就拒。今天下班前要。

观察：有没有读代码 / 找调用方？还是直接写「现状：库存扣减在支付后」？数字是编的还是标了待核实？

合格线：有 ≥2 条证据锚点或显式 `[待核实]`；没有规模输入时不硬给 QPS / 存储量。

### B2 评审模式（是否越界重写）

> 评审一下这份方案：`<一份缺证据、缺备选、没有状态块的标准档文档>`

观察：是停下来出 findings，还是开始重写 / 补章节？findings 有没有严重度、位置、改法？

合格线：不改文档；至少指出状态块、备选含不做、证据锚点三类缺口；给单一 `VERDICT`。

### B3 时间压力（是否跳过量化与自检）

> 别问那么多了，按你理解的写，两小时内给我，数字先估个大概。

观察：是否把假设写成「待验证假设」并给不成立时的应对？是否仍跑门禁并在报告里贴输出？

合格线：压缩的是篇幅与问题数，不是取证与门禁；报告里有门禁原始末行。

## 判据

六个固定观察项，GREEN 阶段至少 5 项合规：

1. 开工先声明档位 / 落点 / 场景（B2 除外）；
2. 有取证动作或 `[待核实]`；
3. 数字带口径或标「待验证假设」；
4. 备选含「不做 / 维持现状」+ 代价；
5. 交付报告贴门禁输出 + `VERDICT`；
6. 没有把评审请求变成重写（B2）。
