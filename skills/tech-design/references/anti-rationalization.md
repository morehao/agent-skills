# 反合理化清单（anti-rationalization）

**定位**：管**流程纪律**，防的是 agent 自己抄近路。它不评文档质量（那是 `quality-bar.md` 的 rubric），也不替代门禁与评审 gate。

用法：动笔前、落盘前、交付前各扫一遍「红牌」；撞上任何一条，先停，按「现实」列的动作做完再继续。

## 红牌（出现即停）

- 「改动小 / 需求清楚，不用取证」
- 「老板/负责人已经口述现状，不用查」
- 「方案已经拍板，备选不用写」
- 「先写完，数字最后补」
- 「拿不准就标 `[假设]`」
- 「门禁 0 error，可以交付」
- 「lens 没问题，能实施了」
- 「评审意见照改就行」

## 借口 → 现实

| 借口 | 现实 | 必须做的动作 |
|------|------|--------------|
| 改动小，不用取证 | 小改动一样会编现状；「现状很简单」通常正是没看代码的征兆 | 至少读 2 个相关文件 + 找 1 条调用方证据，写进取证台账（3 行也算） |
| 先写完再补数字 | 补的时候数字会服从已经写好的结论（倒推），不是估算是圆谎 | 数字与口径先写进「约束与非功能需求」；写不出就标「待验证假设」+ 不成立时的应对 |
| 拿不准就标 `[假设]` | `[假设]` 是「我替你做了决定」，不是免责声明 | 每条 `[假设]` 带默认值 + 不成立时的后果 + 谁确认；读一次代码就能消掉的，不许留成假设 |
| 门禁 0 error，可以交付 | 门禁只查机械项（见 `--list-rules`），语义判断全在 gate | 报告里贴门禁原始输出末行 + gate 的 `VERDICT`；不跑 gate 就写清为什么 |
| lens 没问题，能实施了 | 风险 lens 问的是「有没有坑」，不问「能不能照着干」 | 完整档必跑 builder check；标准档多人排期也跑 |
| 评审意见照改 | lens 也会误判，盲改会引入新矛盾 | 每条先核验（回文档/回代码找反例），分「文档真错 / lens 误判 / 需拍板」；误判写明理由，不静默 `ignore` |
| 用户催得急，跳过后面的自检 | 返工成本是自检的十倍，催你的人不会替你解释漏洞 | 至少跑「门禁 + 贴原始输出」；其余在报告里显式列为未做项与风险 |
| 老板已经口述现状，不用再取证 | 口述是线索不是证据；拍板人的数字一样会错，写进「已确认」就变成替人背书 | 原文标「用户口述、未取证」+ 取证动作 + 责任方，进待确认；不写进「已确认事实」 |
| 方案已经拍板，别写备选了 | 备选不是质疑决策，是给拍板人看代价；门禁把「无备选」判 error | 压到一行「否决：维持现状 + 一句为什么不行」+ 一段「什么情况下不该用」，不写菜单 |
| 赶时间，别跑检查脚本了 | 门禁是秒级不是小时级；跳过等于把自己的自相矛盾留给实施方 | 照跑并把原始末行贴进报告；确有理由不跑，写明未做项与风险 |

## 三条硬闸（其它都能裁，这三条不能）

1. **动笔前有取证台账**：3 行也算，但每行要么有证据锚点，要么显式 `[待核实]`。
2. **交付结论来自输出**：门禁末行、gate 的 `VERDICT`、findings 计数——贴原文，不写「应该没问题」。
3. **每个选型写出「什么情况下不该选它」**：写不出来说明还没想清代价，回去补备选。

## 错题本（每次真实翻车追加一行）

只记「发生了什么 → 当时的合理化原话 → 补了哪条动作」。不写「注意 XX」这种没有动作的提醒。

| 日期 | 场景 | 当时的合理化 | 补的动作（写回本文件或 SKILL.md） |
|------|------|--------------|-----------------------------------|
| 2026-10-26 | B4 权威压力（RED 基线，无技能） | 「口述就是唯一事实基线」「拍板了就不用写备选」 | 红牌补 2 条、借口 → 现实补 3 行；结论：口述标未取证、备选压成否决基线、门禁照跑 |
