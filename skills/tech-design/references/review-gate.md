# 评审 gate（review-gate）

**定位**：把「写完自检」升级为「作者自检 **+** 独立评审」。自检是作者视角，会顺着自己的叙述讲过去；**独立上下文才是这套东西成立的前提**——fresh reviewer 找的是作者讲过去的那部分。所以 gate 只做自检做不了的事，不替代自检。

## 何时跑

| 档位 | 是否跑 | 说明 |
|------|--------|------|
| 完整 | **必跑** | 跨系统、不可逆变更、需要委员会评审的，一个 lens 都不许省 |
| 标准 | 建议跑 | 出现跨团队评审、SLA 承诺、动契约或表结构时升级为必跑 |
| 轻量 | 跳过 | 一次评审能过的小改动，跑 gate 的收益低于成本 |

落点 C（改既有模块）与场景 S3/S4（重构、迁移）即使标准档也按「必跑」对待——这两类最容易漏影响面。

## 三段

### 第 1 段：确定性（先跑，省评审者注意力）

```bash
node <本skill目录>/scripts/check-design-doc.mjs <文档> --tier <light|standard|full> [--upstream <PRD>...] [--strict]
```

- `error` 必须先改完再进第 2 段——机械错误不该占用评审者的判断力。
- `warn` 逐条裁决：改掉，或在文档里显式豁免并写理由（不允许无声跳过）。
- `note` 必须读一遍（`[待核实]`/`[待澄清]`/`[假设]` 是否都收口到开放问题）。
- 退出码非 0 时不进第 2 段。

### 第 2 段：rubric walker（清单判定）

按档位从 `quality-bar.md` 的「评审检查清单」取子集（**那是唯一真源，本节不复述**），逐条判 `pass / gap`，`gap` 必须给位置与改法。

### 第 3 段：并行 lens（独立上下文）

按**场景与专题**选 2–4 个 lens，每个一个独立 subagent：

| lens | 何时选 | 追问 |
|------|--------|------|
| 安全与合规 | 专题含安全、涉敏感数据、需合规审查 | 越权与鉴权边界、密钥管理、日志脱敏、审计留痕 |
| 数据与迁移 | 动表结构、换存储、迁移场景 | 每条索引回指查询？DDL 与正文逐项一致？对账方式？回退窗口？ |
| 运维与可观测 | 完整档、上线形态有变化 | 上线步骤可执行？回滚阈值可观测？容量推导能否复算？ |
| 调用方兼容 | 落点 B/C、改契约或行为 | 谁在调（带证据）？行为变化清单？回归范围与等价性验证？ |

**subagent 契约**（每个 lens 相同）：

- **输入**：文档路径 + 该 lens 的追问清单 + `quality-bar.md` 相关条目 + （可选）上游 PRD / 代码路径。
- **不看作者的中间推理**：只读交付文档与证据，避免被作者叙述带走。
- **输出**：完整评审写到 `<文档目录>/reviews/review-<lens>.md`（子目录，不污染交付目录）。
- **只回摘要**：`VERDICT:` + top 3 findings（严重度 / 位置 / 改法）+ 文件路径。**不把全文塞回父上下文。**
- subagent 不可用时退化为顺序执行：先写文件，再从上下文里冲掉。

### 收口：单一裁决

父代理把三段汇总成一张表，并给**一个**裁决：

```
VERDICT: approve | revise
```

| ID | 严重度 | 位置 | 问题 | 改法 | 处置 |
|----|--------|------|------|------|------|
| G1 | high | 详细设计/数据模型 | 索引未回指查询 | 补「服务的查询」列 | autofix |

处置四选一：`autofix`（直接改）/ `discuss`（需人拍板，进开放问题）/ `defer`（收进开放问题并写触发条件）/ `ignore`（写理由）。

`revise` 的每条发现必须**一次能改完**（位置 + 改法齐全）。approve 后可附非阻断建议。

## 硬规则

- **gate 不替代自检**：交付前自检照跑，顺序是「自检 → 门禁 → gate」。
- **lens 是地板不是菜单**：由场景与专题决定，不能因为「这次应该没安全问题」裁掉安全 lens。
- **报 tier 不报流水账**：先一句裁决，再 critical/high；medium/low 收进「另有 N 条见 reviews/…」。
- **不可执行的建议不进 findings**：`建议优化`、`可读性欠佳` 这类没有位置与动作的，写出来只是噪音。
- **评审者不改文档**：除 `autofix` 由父代理执行外，lens 只读。

## 反模式

| 反模式 | 症状 | 改法 |
|--------|------|------|
| 自己评自己 | 作者跑 gate 并自我 approve | 换独立上下文（subagent），作者只做裁决与 autofix |
| lens 被裁掉 | 「这次没安全问题」跳过安全 lens | lens 由场景/专题决定，不由作者心情决定 |
| 全文回流 | 4 份评审全文拼进父上下文 | 只回 verdict + top3 + 路径 |
| 意见不可执行 | 「建议再完善一下」 | 指出失败条件、位置、改法 |
| 没有裁决 | 报一堆问题不说 approve/revise | 必须给单一裁决，否则评审者无法收尾 |
| 用 gate 当自检 | 跳过交付前自检直接跑 gate | 自检先跑；gate 只补独立视角 |
