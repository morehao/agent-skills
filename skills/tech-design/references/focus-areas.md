# 方案专题（focus-areas）

专题是**可多选的加固方向**，不是文档分类标签。它决定三件事：

1. **重心**：骨架里哪几节要写深、写细；
2. **必答项**：该方向绕不过去、评审一定会问的技术问题；
3. **可裁剪**：与本方案无关、可以删掉的章节。

专题**不改变档位**（篇幅见 `templates.md`），也**不承担过程义务**——迁移、兼容、回滚、等价性验证等「从现状到目标的过程」由 `scenarios.md` 的场景义务包定义；本文最后一节「迁移手法」只提供可复用的技术手段。

多个专题叠加时，同一章节取并集加深；专题必答项与模板骨架冲突时以专题为准，并在文档中说明取舍理由。

## 专题判定速查

| 专题 | 命中信号（用户表述举例） |
|------|--------------------------|
| 架构设计 | 系统架构、微服务拆分、模块化、平台化、跨系统集成 |
| API 设计 | 接口/API/OpenAPI、REST/RPC/gRPC、对接第三方、协议、对外开放 |
| 数据模型设计 | 数据库设计、表结构、ER 图、索引、分库分表、存储选型 |
| 性能与容量 | 高并发、QPS/RT 不达标、瓶颈、缓存、限流、压测、容量规划 |
| 安全 | 认证授权、登录态、数据加密、防爬防刷、权限模型、合规 |
| 迁移手法 | 需要双写/影子流量/流量回放/对账/灰度切流/开关等手段时（场景为 S3/S4/S5 时通常需要） |
| （无专题） | 未命中以上任一，或多方向但无明显侧重 → 按模板原样展开 |

> 落点（新系统 / 宿主新模块 / 既有模块）不是专题，它归「场景判定的第 0 问」（`scenarios.md`）；落点决定取证对象与义务增量，与专题正交。

## 架构设计

- **重心**：总体架构——设计原则、架构图、系统边界与职责、核心流程、数据流转、部署形态与资源拓扑。
- **必答项**：
  - 架构图**按职责选工具**：结构类（拓扑/分层/边界/部署）用 **SVG**（经 `svg-maker` 产出），时序与线性流程用 Mermaid；同一张图不做双份，阈值见 `quality-bar.md`。
  - 「模块/服务 × 职责」表：职责不重叠、不遗漏，并标明**数据所有权**归属（谁能写、谁只能读）。
  - 单点与故障域：哪些组件挂了会整体不可用，如何降级/容错；可用性按 `quantification.md` 做串联预算。
  - 调用链深度：跨服务调用次数、超时与重试策略（重试必须配退避 + 幂等，否则放大故障）。
  - 部署形态与资源拓扑：环境、实例与副本、机房/可用区、依赖组件（DB/缓存/MQ/外部服务）的部署位置与网络通路；完整档必填，标准档一句或一张图。
  - 演进路径：与现状的差距、分期切分点，每期可独立上线、可独立回退。
- **可裁剪**：详细接口定义与字段级表结构——归「API 设计」「数据模型设计」专题；架构章节只写数据所有权归属，DDL 收在该专题的附录（`data-model.md`），不在本节重复。
- **联动**：文档内结构类图与独立 SVG 交付物都走 `svg-maker`（后者交付物就是 `.svg` 本身，不写进方案正文）。

## API 设计

- **重心**：接口定义、交互时序（`sequenceDiagram`，Mermaid 强项）、错误与兼容。
- **必答项**：
  - 接口清单：方法/路径/请求响应示例、错误码约定、鉴权方式（示例原则见 `quality-bar.md`）。
  - 幂等与重试语义：哪些接口可安全重试，幂等键怎么传。
  - 版本与兼容策略：破坏性变更如何发布（新增字段默认值、废弃周期、双版本并行期）。
  - 规模上界：分页/批量/超时上限，防止一次拉全量；接口目标 QPS 按 `quantification.md` 估。
  - 「不做什么」：本次不开放的接口能力，防止接口膨胀。
- **可裁剪**：成本分析、压测方案等与企业级无关章节。

## 数据模型设计

- **重心**：领域实体、关系与生命周期、表结构、一致性。
- **落法**：**正文用表格讲设计 + 一张简版 ER 图讲关系 + DDL 收进附录**——三层职责划分、三张表的列、ER 图与 DDL 规范、落盘前自检全部见 `data-model.md`；本节只列绕不过去的必答项。
- **必答项**：
  - **从需求梳理领域实体、关系与生命周期**（**实体先于表结构**）：实体从哪来、怎么创建/变更/归档/删除，有状态流转时给 `stateDiagram-v2`。
  - **简版 ER 图**（一张，必给）：只含实体、主键与关系基数，**不画全字段**；实体 ≤ 约 10 用 Mermaid `erDiagram`，实体多/关系交叉/需按模块分区改用 **SVG**（经 `svg-maker`），阈值见 `data-model.md`。
  - **正文三张表**：实体清单（数据所有权、生命周期、量级与增速）、字段表（业务含义与口径）、索引与查询匹配表。
  - 索引设计与**查询匹配**：每个索引对应正文哪条查询、是否覆盖索引、写入放大的代价；没有查询支撑的索引删掉或标 `[待核实]`。
  - **DDL 只在附录**：`### 数据模型 DDL` 是唯一可执行真源，正文不贴建表语句；S2/S4 另给变更 DDL 与**回退 DDL**（`scenarios.md`）。
  - 读写比与访问模式假设（决定范式/反范式、宽表/多表）。
  - 一致性取舍：强一致/最终一致、事务边界、跨库一致性方案。
  - 分库分表只在该需求明确时展开，且必须给路由键、扩容方式、跨分片查询方案。
  - 存储量按 `quantification.md` 推（单条 → 增量 → 规划期总量），落在实体清单表的量级列。
- **可裁剪**：消息与异步、可观测性等无关章节（轻量/标准档）。

## 性能与容量

- **重心**：基线、瓶颈、优化方案取舍与验证。
- **必答项**：
  - 现状基线与目标：QPS、RT（P99）、资源水位——按 `quantification.md` 给推导，不拍脑袋。
  - 瓶颈先给**假设与验证手段**（压测/采样/链路追踪/AB 对比），再给优化方案。
  - 每项优化写「预期收益 + 代价 + 回退开关」；缓存方案必须写失效策略与穿透/雪崩防护。
  - 容量规划：存储/带宽/连接的规划期总量 + 扩容触发阈值。
- **可裁剪**：与性能无关的企业级章节；轻量/标准档给验证步骤即可，完整档才展开压测方案。

## 安全

- **重心**：资产与信任边界、威胁与防护、审计与合规。
- **必答项**：
  - 资产清单与信任边界：谁可信、什么数据敏感、数据流向哪些外部系统。
  - 认证/授权模型：身份来源、权限粒度（RBAC/ABAC）、越权防护（水平/垂直越权分别给措施）。
  - 数据保护：传输与落库加密、密钥管理、脱敏；**日志与错误信息中不得出现明文凭据或敏感字段**。
  - 威胁—防护对照表：注入、重放、暴力破解、越权、敏感信息泄露等逐条给措施。
  - 审计与合规：留存什么、留多久、谁能查。
- **可裁剪**：性能压测、成本分析等无关章节。

## 迁移手法（手段库）

本节只提供**可复用的技术手段**。义务（必答项、章节增删、验收与回滚形态）由场景定义：
结构重构见 `scenarios.md` S3，替换与迁移见 S4，下线与废弃见 S5。

- **双写与双读**：新旧载体同时写、校验期双读比对；切换顺序是「先双写 → 校验 → 切读 → 停旧写」。
- **影子流量 / 流量回放**：把生产流量复制到新实现（不返回结果），或回放历史请求做结果比对；用于行为等价性验证。
- **对账**：以明确口径（条数/汇总值/逐条哈希）比对新旧数据，规定抽样比例、比对频率与**差异处理规则**（以哪边为准、如何修补）。
- **灰度切流**：按用户/租户/流量比例逐步切换；每步给进入与退出判据，异常时能一键指回旧路径。
- **绞杀者模式（strangler fig）**：新旧并存，按能力或路由逐块把流量从旧实现挪到新实现，旧实现逐步空心化后下线。
- **开关与熔断**：功能开关、路由开关、只读降级；开关必须有默认值、生效范围与清理计划（长期残留的开关本身是技术债）。
- **不可逆动作的执行前检查**：删表/删数据/切主库前，确认零写入、备份可恢复、回退窗口状态、审批人。
