# Disk Cleanup

空间回收的统一入口：**先测量 → 再报告 → 用户勾选 → 才删除**。

磁盘清理是一个动作，不是一串预设清单。系统缓存、开发工具缓存、本地数据库（如 opencode）都只是同一次「腾空间」里的不同对象，按占用大小决定先动谁，不要一上来就敲删除命令。

## 铁律

1. **先查询后删除，最终清理哪几项由用户勾选**。任何 `--clean` 之前先跑只读模式；清单里每项都要带编码与实测大小；即便用户说了「清理吧」，也要把清单变成多选项让他勾——不许自动全选、不许替他决定、不许只报一句「总共能清 20G」就开删。
2. **不代删用户数据**。聊天记录、浏览器配置、虚拟机磁盘镜像、iOS 设备备份、邮件与信息附件：只报告大小与路径，给出应用内清理入口，由用户自己动手。
3. **sudo 交给用户的终端**。agent 执行环境没有 TTY，`sudo -v` 必然失败；涉及 `/tmp` 与 Time Machine 快照的 `--clean`，把完整命令交给用户在自己的终端执行，不要反复重试，更不要拼 `echo 密码 | sudo`。
4. **平台门**。`mac_cleanup.sh` 仅 macOS；数据库脚本只处理本机的 opencode 库，不做通用 SQL 清理。
5. **不可逆前先备份**。数据库瘦身前先给 `.backup` 命令；12G 级大库不要用 `cp`/`tar` 全量复制。
6. **不虚构数字**。占用、释放量一律来自命令输出；取不到就写「未知」，不做估算。

## 流程（一条线，不分叉）

**0. 先看用户有没有说明**

- **用户没有任何文字说明**（空消息、只 `@` 了技能、`/cleanup` 没带参数）→ **不执行任何脚本**，先给编号选项，等用户选：
  1. 只看占用（只读，不删）
  2. 选勾清理（先出清单 → 你勾选 → 预览确认 → 执行；sudo 项交你终端）
  3. 只处理本地数据库（如 opencode）
  4. 取消
  不要替用户选默认项，也不要「顺手先查一下」——查询也要先问。
- 用户带了具体说明（如「看看什么最占地方」「清一下缓存」「opencode 太大」）→ 按其范围直接进入第 1 步。

**1. 测量（只读）**

- macOS：`bash scripts/mac_cleanup.sh`（默认只查询，不删任何东西）；需要核对编码时 `--list`
- 非 macOS：`df -h` / `du -sh *` 只读排查，并说明本技能只有 macOS 清理脚本

**2. 报告与分类**

把测到的项整理成三块交给用户：

- **可勾选清理项**：表格四列——勾选项 / 编码（`--only`）/ 实测大小 / 删除后要付什么代价（应用首次打开变慢、镜像重新 pull、构建重跑等）。数据只取第 1 步输出；未安装/未找到的项直接不列。
- **需应用内处理**：只给大小与路径，不代删。
- **需 sudo**：`/tmp`、Time Machine 快照，标明要由用户在自己的终端跑。

报告完问一句要不要按清单勾选清理；用户说「先这样」就到此为止，不进入第 3 步。

**3. 让用户勾选（关键一步，不许代选）**

用提问工具（dsh：`ask_user_question`，多选；opencode 用等价的多选提问）把第 2 步的「可勾选清理项」变成选项，**同时给出每项大小与代价**：

| 勾选项 | 传给 `--only` 的编码 | 说明 |
|---|---|---|
| 用户缓存与日志 | `caches,logs` | 只删 1 天前的缓存、7 天前的日志；应用首次打开会慢一点 |
| 临时文件 | `tmp,varfolders` | `/tmp` 需 sudo，只能交用户终端 |
| Time Machine 本地快照 | `snapshots` | 需 sudo，交用户终端 |
| 废纸篓 | `trash` | 清空后不可恢复 |
| 开发缓存 | `xcode,toolcache` | Xcode DerivedData、npm/pnpm、go、uv、playwright 等；下次构建/安装重下 |
| 构建大件 | `bigbuild` | ipsw、Homebrew、CocoaPods、Gradle、iOS DeviceSupport、旧模拟器 |
| Docker 无用资源 | `docker` | 删未使用镜像与停止的容器，镜像要重新 pull |
| opencode 数据库 | 不传（走 `cleanup-opencode.sh`） | 需先关闭 opencode、先备份；库存在才列出，<500MB 标「收益有限」 |

- 每个选项的说明里带上**本次实测大小**；低风险项标「（推荐）」，风险项写清代价，不要把选择包装成「一键优化」。
- 用户开头已点名范围（如「清一下缓存」）时，把对应项标成建议并说明，但仍要把完整清单给他确认，不能只清他提到的那一项、也不能顺手加别的。
- 至少保留一个「暂不清理」选项；用户只选它 = 本次不清理，直接结束，不要再追问。
- **没勾的项一律不动**。用户回「随便」「你看着办」时重问一次，仍不明确就按「只看清单」处理，不要脑补。
- 没有提问工具时：输出编号清单，让用户回编号（如 `1,3,5`）。

**4. 执行（只跑勾选项）**

- 勾选结果映射成 `--only <编码>`，先自查：`--clean --dry-run --only <编码>`，确认预览与勾选一致（防脚本漂移），再 `--clean --only <编码>`。
- 勾选里含 `tmp`、`snapshots` → 拆出来，把 `--clean --only tmp,snapshots` 的完整命令交给用户终端；agent 侧只跑非 sudo 部分。
- 勾了 opencode 数据库 → **放在磁盘清理之后**（要闭库，可能顺带结束当前会话）：先备份、再跑 `cleanup-opencode.sh`，与磁盘清理分开汇报。
- 某步失败或被跳过不要吞掉，写进回执。

**5. 复核**

`df -h /` 前后对比 + 实际执行清单 + 未勾选/跳过项及原因。

## 按需加载

执行前 `read references/cleanup.md`：清理项编码与阈值、勾选命令示例、sudo 交接方式、数据库瘦身的安全边界、需人工处理的手动清单。

本技能只有一个分支（`cleanup`）——一次完整的空间回收流程；`/cleanup` 命令直接落到它。

脚本路径相对本文件所在目录：`skills/disk-cleanup/scripts/`。不要去找旧仓库里的副本。

## 交付回执

一次清理任务结束，回执至少包含四块：

- **空间**：清理前后 `df -h /` 的可用值，以及实际释放量（没有提升就如实说明，别归因给「系统延迟」除非确实如此）。
- **你勾了什么**：用户勾选的项与对应编码。
- **做了什么**：逐条列出实际执行的清理项；同样列出**跳过了什么、为什么**（未勾选、权限不足、未安装、用户数据不代删）。
- **要用户接手的事**：应用内清理入口、需要在用户终端跑的 sudo 命令、数据库备份命令、重启再看的建议。
