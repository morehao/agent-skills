# Disk Cleanup

空间回收的统一入口：**先测量 → 再报告 → 用户明确同意后才删除**。

磁盘清理是一个动作，不是一串预设清单。系统缓存、开发工具缓存、本地数据库（如 opencode）都只是同一次「腾空间」里的不同对象，按占用大小决定先动谁，不要一上来就敲删除命令。

## 铁律

1. **先查询后删除**。任何 `--clean` 之前先跑只读模式，把占用清单交给用户；用户只说了「清理吧」但没看过清单时，先给清单。
2. **不代删用户数据**。聊天记录、浏览器配置、虚拟机磁盘镜像、iOS 设备备份、邮件与信息附件：只报告大小与路径，给出应用内清理入口，由用户自己动手。
3. **sudo 交给用户的终端**。agent 执行环境没有 TTY，`sudo -v` 必然失败；涉及 `/tmp`、`/var/folders`、Time Machine 的 `--clean`，把完整命令交给用户在自己的终端执行，不要反复重试，更不要拼 `echo 密码 | sudo`。
4. **平台门**。`mac_cleanup.sh` 仅 macOS；数据库脚本只处理本机的 opencode 库，不做通用 SQL 清理。
5. **不可逆前先备份**。数据库瘦身前先给 `.backup` 命令；12G 级大库不要用 `cp`/`tar` 全量复制。
6. **不虚构数字**。占用、释放量一律来自命令输出；取不到就写「未知」，不做估算。

## 流程（一条线，不分叉）

**0. 先看用户有没有说明**

- **用户没有任何文字说明**（空消息、只 `@` 了技能、`/cleanup` 没带参数）→ **不执行任何脚本**，先给编号选项，等用户选：
  1. 只看占用（只读，不删）
  2. 预览将清理哪些（不实际删除）
  3. 实际清理（sudo 三步由你在终端执行）
  4. 只处理本地数据库（如 opencode）
  5. 取消
  不要替用户选默认项，也不要「顺手先查一下」——查询也要先问。
- 用户带了具体说明（如「看看什么最占地方」「清一下缓存」「opencode 太大」）→ 按其范围直接进入第 1 步。

**1. 测量（只读）**

- macOS：`bash scripts/mac_cleanup.sh`（默认只查询，不删任何东西）
- 非 macOS：`df -h` / `du -sh *` 只读排查，并说明本技能只有 macOS 清理脚本

**2. 报告与分类**

把测到的项分成三类交给用户，各带大小：可安全自动清理 / 需应用内清理 / 需 sudo 由用户在终端执行。

**3. 执行（拿到明确同意后）**

- 缓存、日志、临时文件、Time Machine 快照、开发工具缓存 → `mac_cleanup.sh --clean`。先跑 `--clean --dry-run` 让用户过一眼；sudo 三步按铁律 3 交接。
- 本地数据库瘦身（如 opencode）→ **只在用户点名、或该库明显偏大时才做**，不是每次磁盘清理的默认步骤。先备份、先闭库，再跑 `cleanup-opencode.sh`。

**4. 复核**

`df -h /` 前后对比 + 实际执行清单 + 跳过项及原因。

## 按需加载

执行前 `read references/cleanup.md`：清理项与阈值、sudo 交接方式、数据库瘦身的安全边界、需人工处理的手动清单。

本技能只有一个分支（`cleanup`）——一次完整的空间回收流程；`/cleanup` 命令直接落到它。

脚本路径相对本文件所在目录：`skills/disk-cleanup/scripts/`。不要去找旧仓库里的副本。

## 交付回执

一次清理任务结束，回执至少包含三块：

- **空间**：清理前后 `df -h /` 的可用值，以及实际释放量（没有提升就如实说明，别归因给「系统延迟」除非确实如此）。
- **做了什么**：逐条列出实际执行的清理项；同样列出**跳过了什么、为什么**（权限不足、未安装、用户数据不代删）。
- **要用户接手的事**：应用内清理入口、需要在用户终端跑的 sudo 命令、重启再看的建议。
