# Disk Cleanup

## 定位：一条线，不分叉

一个动作，不是一串预设清单：**测量 → 报告 → 用户勾选 → 预览 → 执行 → 回执**。

脚本在本文件同级的 `scripts/`：`mac_cleanup.sh`（macOS 磁盘，29 个编码）与 `cleanup-opencode.sh`（本机 opencode 库，单对象）。云盘、外接盘、Windows 清理不适用。

## 铁律（只写脚本拦不住的那部分）

1. **先测后删，删哪几项由用户勾选。** 任何 `--clean` 之前先跑只读查询；清单每项都带编码与实测大小；即使用户说「清理吧」，也要把清单变成多选项让他勾。agent 永远用 `--clean --only <勾选项>`，不用 `--all`——脚本只拦「`--clean` 不带 `--only/--skip/--all`」，拦不住你替用户全选。
2. **不代删用户数据。** 聊天记录、浏览器配置、虚拟机镜像、iOS 设备备份、邮件与信息附件：只报大小与路径，给应用内入口，由用户自己动手。
3. **sudo 与沙箱外的删除交用户终端。** agent 没有 TTY，`sudo -v` 必失败；含 `tmp`、`snapshots`、`systemlogs` 或 `/Library` 下条目的 `--clean`，把完整命令交给用户在自己的终端跑。不要 `echo 密码 | sudo`，不要为此改脚本或换路径。
4. **保护清单命中不许绕过。** 被挡下的路径（`reason=protected`）只能向用户解释清楚，**不得**改用 `rm`、`find -delete`、换等价路径、或改掉 protect 文件再删。`hard` 项是安全底线，不是建议。
5. **不虚构数字，且分双口径。** 数字只来自命令输出，读不到就写「读不到」；报告必须同时给**目录总量**与**本次可删量**——只删阈值项的编码两者能差一个数量级，只报目录总量等于帮用户虚报收益。

## 流程 0–5

**0. 无说明先给选项。** 用户没带具体说明（空消息、只 `@` 技能、`/cleanup` 无参数）→ 不跑脚本，先给编号选项等他选：1) 只看占用 2) 选勾清理 3) 卸载残留 4) 取消。不要替他选默认项，也不要「顺手先查一下」。

**1. 测量（只读）。** `bash scripts/mac_cleanup.sh` 默认查询；要编码用 `--list`；问「什么最占地方」用 `--top 10`；问「哪个 App 卸了还留着东西」看 orphans（`--orphans-list` 列全部）；要结构化结果加 `--json`。非 macOS：只用 `df -h` / `du -sh *` 排查，并说明本技能只有 macOS 清理脚本。

**2. 报告四块。**
- **可勾选**：表格给「勾选项 / `--only` 编码 / 目录总量 / 本次可删量 / 代价」。可删量取脚本的「本次可删」列，不要拿目录总量顶替。
- **需应用内处理**：只给大小与路径（iOS 备份、聊天记录、虚拟机镜像、iCloud 本地副本）。
- **需 sudo**：`tmp`、`snapshots`、`systemlogs`、`/Library` 下的残留，标明要由用户终端跑。
- **只报告**：`reports[]` 里的系统级大户与 `orphans` 候选；不列入勾选项，不给「一次全删」选项。

**3. 勾选。** 用提问工具（dsh：`ask_user_question`，多选）把可勾选项变成选项，**每个选项带实测大小与代价**；低风险标「推荐」，风险项写清后果；至少留一个「暂不清理」。用户回「随便」就重问一次，仍不明确按「只看清单」结束。没有提问工具时输出编号让用户回数字。

**4. 执行。** 勾选映射成 `--only <编码>`，先 `--clean --dry-run --only <编码>` 复核预览与勾选一致，再 `--clean --only <编码>`。含 sudo 编码的拆出来交终端；`orphans` 只报告，删除要逐条 `--orphans-delete <路径>`（路径须存在、是扫描根直接子项、在本次候选里，否则 `exit 1`）。失败与被跳过的项不吞。

**5. 回执。** 按下面「交付回执」写，只写一遍。

## 判断力只能收窄

排序、解释、劝退是你的活；加路径、加范围永远不是。

- **可排序**：按「本次可删量」降序，不按目录名、也不按你的印象。
- **可解释**：每项写清代价——需重新下载、需重新构建、首次启动变慢、不可恢复。
- **可劝退**：可删量小、代价大时直接说「这项不值得清，建议留着」并给理由；劝退比凑成果重要。
- **不加范围**：不自创路径、不放宽 `--projects-roots` 去扫更大范围、不往 `--only` 里偷偷加项、不用 `rm` 补脚本没覆盖的地方。
- **分来源**：数字标「脚本实测」；「这目录应该没人用了」这类属于你的推断，必须标成推断，且不能当删除依据。

## 沙箱三步

1. **症状**：删除命令报 `Operation not permitted`、`--json` 里 `items[].reason=denied-sandbox`、或执行完 `disk.freed_kb=0` 而可删量明明不为 0。
2. **含义**：这是**沙箱/权限拒绝，不是已清理**。文件还在，报告里的 `partial`/`failed` 才是真相；不要把 `freed_kb=0` 解释成「本来就没东西」。
3. **动作**：改用可写沙箱（目标在工作区内）或把同一条命令交用户终端；不要反复重试、不要 `sudo` 顶替沙箱权限、不要换 `rm` 绕。

## 交付回执

一次清理任务结束只写这一段，**第一行先给结论**（清没清、腾出多少、有什么没做成）：

- **空间**：`df -h /` 前后对比；释放量分两行——各清理项实测可删合计（估算，`disk.estimated_freed_kb`）与 `df` 差值（旁证，`disk.df_delta_kb`）。差值 ≤0 就如实说明，不归因「系统延迟」；`docker` 回收在虚拟磁盘内部，宿主 `df` 可能不变。
- **勾了什么**：用户勾选的项与对应 `--only` 编码。
- **做了什么**：实际执行的项逐条列出；同时列出**跳过了什么、为什么**（未勾选、需 sudo、沙箱拒绝、在用、受保护、用户数据不代删）。卸载残留要写**实际删掉的具体路径**与被跳过的路径。
- **要用户接手的事**：应用内清理入口、需在自己终端跑的 sudo 命令、数据库备份命令、重启后再看的建议。
