# 多图批量产出工作流（子代理并行 + 两道关）

> 当一篇文档需要在同一轮产出 ≥3 张 SVG 图时加载（常见于 `architecture-design.md`）。

## 为什么不能"交给模型画完就算"

LLM / 子代理产出的 SVG 有一个稳定的失败模式：**看起来对，边连错了**——缺一条边、多一条边、分支挂到错的节点上，而所有文字标签都正确。缩略图看不出，渲染也不报错。所以必须有**两道关**：

1. **程序关**：`scripts/audit-svg-topology.mjs` 逐条打印 `起点 → 终点`，与期望边清单比对。
2. **人眼关**：`scripts/render-svg-preview.mjs` 出 PNG（必须先把 `var()` 展平成字面色，否则 librsvg 渲染全黑，看不出对错）。

## 并行规格模板（每个子代理一份，缺项必出问题）

| 必给项 | 说明 |
|---|---|
| 目标路径 | 绝对路径，一图一文件；**明确"只写这一个文件、不要改其它文件"**（否则会顺手改文档） |
| 图的语义 | 直接给 mermaid 源码或节点/边清单，写明"**语义必须与它完全一致**" |
| 布局要求 | 分几段/几列、每段放什么、跨段连线怎么走；**长链（>12 节点）必须换布局**，禁止排成一列 |
| 风格块 | 整段 `<style>` 原样给出（含 `:root` 变量与暗色媒体查询），要求逐字使用 |
| 硬性规范 | 固定 `viewBox`；**字面 `<title>`/`<desc>`（不带属性）**；根元素不写 `width`/`height`；先连线后节点；每条边 `fill="none"` + `marker-end`；盒内 ≥24px；只用系统字体栈；无 JS/图片/渐变/远程资源 |
| 配色语义 | 按类名分配（input / process / storage / external / risk / neutral），不写死颜色 |
| 自检要求 | 交付前做 XML 解析 + 越界矩形检查 + 逐盒文字宽度核算，并**贴出自检输出** |
| 交付格式 | 路径 + viewBox + 节点数 + 边数 + 自检结果 |

## 主 agent 的收尾动作（不可省）

1. 逐图跑 `audit-svg-topology.mjs`，与期望边清单核对（**边数对不上就先别接进文档**）。
2. 逐图渲染 PNG 目视一遍，至少看最复杂的那张。
3. 统一收口：中文标点（`:` → `：`）、根元素写法（只留 `viewBox`）、资产命名（英文语义名、无序号前缀）。
4. 接入文档时补"图前导读 + 图后要点"，否则触发 `[FIGURE-ONLY]`。
5. 收尾跑一次 `scripts/check-narrative-all.mjs`。

## 已知坑（都真实发生过）

| 坑 | 表现 | 对策 |
|---|---|---|
| `<title id="...">` | 下游校验按字面匹配，报 `[SVG-NO-META]` | 统一写不带属性的 `<title>`/`<desc>` |
| 根元素加 `width`/`height` | 与同目录其它资产写法不一致 | 只保留 `viewBox` |
| 同批图三种画法 | 盒子高低、间距不一 | 在规格里固定盒高与行距，要求复用同一套坐标规则 |
| 子代理报"节点数与要求不一致" | 规格里的节点数是手写估计 | **以 mermaid/清单为准**，节点数从源码数出来 |
| 图上文字超宽 | 中文按字号、拉丁按 0.55-0.6 倍字号估算 | 盒子宁宽勿窄；超宽就拆两行 |
| 预览显示全黑 | rsvg 不解析 CSS 自定义属性 | 用 `render-svg-preview.mjs` 展平 `var()` 后再渲染 |
