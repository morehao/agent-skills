# 常见错误与对策（查表）

> 由 SKILL.md「常见错误与对策」按需加载。写作/校验中遇到反复问题时对照自查；对应铁律的完整表述见 SKILL.md 正文。

| 错误 | 修正 |
|------|------|
| 信任模型/记忆的行号 | 只信 verbatim 锚点行（每条引用首末行双锚点），程序在真实文件按位置校验 + 搜索重定位真行号。 |
| 定位失败当作定位成功一样处理 | 失败必须标 `[UNVERIFIED]`，不能和已验证引用长得一样。 |
| 没先读现有文档就重写 | 增量铁律 1：先读。 |
| 已有解读却想全量重来、直接在旧文档上覆盖改写 | 默认增量；用户明确要求全量时**先删除既有解读**（项目目录全部文档 + 分类索引行 + 子文档索引章节，经用户确认）再走全新分析模式，不在旧文档上原地覆盖，避免残留子文档与索引错位（删除同样不代为 git commit）。 |
| 凭感受大改结构 | 结构是资产，既有 `##` 章节原样保留。 |
| 只改正文、漏掉能力清单/技术栈/图表里的数字 | 全篇 grep 核对所有出现处。 |
| 文档自称 v0.8 却没核对真实上游版本/diff | 增量铁律 3：先取真实依据；拿不到就声明代码快照比对。 |
| 没定基线就开写（随手拿 cwd / 默认分支当解读对象） | 先跑 `scripts/select-baseline.mjs`：稳定 tag > 稳定分支 > 默认分支 > 无 main/master 兜底；基线未定不得进入探索（[version-baseline.md](version-baseline.md)）。 |
| 远端地址裸 `git clone --depth=1`，恒取默认分支、还丢了 tags | 先 `git ls-remote`（tags/heads/symref HEAD）枚举选基线，再 `clone --branch <ref>`；需要 diff 历史用 `--filter=blob:none`。 |
| 仓库没有 main/master 就认为无法分析，或默默挑当前分支 | 走兜底矩阵（远端 HEAD → `origin/HEAD` → 非特性当前分支 → `trunk`/`develop`/`default`/`next` → 最近的非特性分支 → 最新 tag），全空才交用户；特性分支永远不当主干。 |
| 把最新 tag 直接当"稳定版"解读（它可能已停更多年） | `[BASELINE-STALE]`（落后默认分支超阈值 / 距今过久）必须请用户确认，并在产物中注明"已确认接受其陈旧度"。 |
| 校验在 A 份代码上、写作在 B 份代码上 | `source_repo` 必须是**基线工作树**，探索/写作/`verify-references.mjs` 三者同一棵树（脚本只读磁盘，换树则行号核对无意义）。 |
| 在用户脏工作树上直接 `git checkout` 覆盖未提交改动 | 先 `git status --porcelain`；脏树不静默覆盖，走 `git worktree add` 兜底或经确认后 stash；收尾恢复原 HEAD 并报告。 |
| 解读完没记录基线，下次增量不知 diff 起点 | 基线写进 README 概览「解读基线：`<ref>`（`<sha>`）」+ `CHANGELOG.md` 顶部「依据：`<ref>@<sha>`」；不写 frontmatter（版本类字段仍不入 frontmatter）。 |
| 新建文档后忘了更新分类索引 | 收尾三步不能跳。 |
| 把 README 翻译一遍充深度 | 这是提炼不是翻译；深度不足标 [WIP]，按 analysis-guide 写深。 |
| 默认堆满完整代码块当深度 | 叙述优先：设计观点写成散文，编码细节用 `文件:行号` 指向源码，仅用户明确要求某具体实现时才贴码（见 [grounding-guide.md](grounding-guide.md)）。 |
| 每处引用贴整段代码（`> [path] — 完整 code`） | Grounding 指纹与展示分离：正文只放「结论/权衡 + `[路径:行号]`」，完整实现交给读者点源码。 |
| 指纹注释整段贴源码（`<!-- snippet: 整块代码 -->` 当指纹） | 指纹只取引用区间**首末行双锚点**（各 ≤1 行、截断 ≤80 字符、含 `--` 用 base64）；整段源码永远不进解读文档，旧 snippet 格式仅作存量兼容。 |
| 把流程写成纯文字长段 | 启动流程/请求链路/生命周期/跨模块时序命中即给**图**（工具按 [kb-repo-rules.md](kb-repo-rules.md) 选型规则）；文字只做图外补叙。 |
| 篇幅失控、该拆未拆 | 关注 README 是否塞进多关注面、是否拖沓，而非死守行数；该拆子文档就拆，不为达标压缩有效内容。 |
| 拆了子文档却忘在 README 列链接 | 按 [kb-repo-rules.md](kb-repo-rules.md) 的索引约定：README 专章列全 + 正文/导读表就近内链，新增即回写。 |
| 把数据模型写成字段清单罗列 | 按 [data-model-guide.md](data-model-guide.md) 五要素写（ER 图 + 每表字段表 / 存储选型 / 核心表设计 / 演进策略 / 读写路径），写成设计而非数据字典。 |
| 凭"是不是业务应用"主观跳过数据模型（如库/框架只当自带表看待） | 跑 [data-model-guide.md](data-model-guide.md)「数据模型主动探测」的程序化信号（`*.sql` / `migrations/` / models 实体 / ORM 建表入口），命中即触发五要素成文，不以项目形态为由省略。 |
| 语言惯用法只写"用了 goroutine/channel"这种 What | 按语言惯用法维度深挖 Why：为什么选这个并发/所有权/状态管理模型、代价是什么、落在具体设计语境与 `文件:行号`；不写成语言教科书。 |
| 只看产品类型、漏了语言维度的深层主题 | 两种维度都要过一遍 [dimension-triggers.md](dimension-triggers.md)「关注面触发判据」；语言维度命中即作为候选关注面，够深独立成文、不够并入小节。 |
| 标题写 `## 0.` / `## 1.` / `## 第N部分` | 靠 Markdown `##/###` 天然层级，标题用语义词（决策一、亮点、问题）而非纯数字前缀，列表项序号不算标题。 |
| 整段英文引用且无中文解读 | 优先中文转述；保留英文原句必须紧跟中文解读；正文中文为主，标识符保留英文。 |
| 单文件暴力拼全部源码进提示词 | 超 token 且污染上下文；中小库打包相关文件，大库（>5 万行）转 parallel 流程。 |
| 大库不会分流、硬塞单 agent | 走 [flow-new.md](flow-new.md)「规模门控·复杂度×规模分流」：判定深度信号，大而深走 [large-repo-workflow.md](large-repo-workflow.md) 并行，否则按路径收口。 |
| 大而浅的仓库硬走并行深度流程 | 判定"深/浅"信号（模块独立、无统一核心链路/哲学、README 按功能点列清单 → 浅），退化单 agent 按模块群分组解读，不为行数产出无深度子文档。 |
| 小但复杂的仓库当常规小项目处理 | "小但复杂"走路径 A：单篇按四要素深挖 + 多个 sequenceDiagram 拆流程 + 反事实推理，不因行数少就写成流水账。 |
| 把多关注面项目压成一个 README | 按关注面拆子文档，README 只作索引/概览（复杂度判据，非行数）。 |
| 为了拆而拆、每篇没深度 | 拆前检查每个关注面是否有可展开的 Why/权衡/源码佐证；凑不够的退化为单文件。 |
| 引用用裸文件名不对应真实路径 | 一律仓库相对路径，防穿越校验后落库。 |
| 引用无行号 | 引用须带真实行号，用首末行锚点经程序重定位后补齐。 |
| 把 cwd 当成知识库仓库直接写入 | 先做 kb_repo 判定，命中排除信号或拿不准时必须走用户选择分支。 |
| 把源码仓库误判为知识库仓库 | 检查 go.mod/package.json 等工程清单，命中即视为排除信号。 |
| 图渲染报错或 mermaid+svg 重复 | 落盘前跑 `scripts/check-mermaid.mjs` 全 `OK`（`mermaid.parse()` 真解析），有 `[MERMAID-ERROR]` 修复至通过；同一张图只保留一种形式。 |
| 标签内 `<br>` 乱用导致预览挤压 | 换行统一用无斜杠 `<br>`、只用在引号标签内；长标签在语义断点补 `<br>`，跑 `check-mermaid.mjs` 使 `[MERMAID-WARN]` 收敛为 0。 |
| 读源码文件无路径防护 | realpath 规范化 + 公共前缀白名单校验（`verify-references.mjs` 内已实现），对 kb_repo 同样适用。 |
| 落盘后擅自 git commit | 只列变更清单，是否提交交给用户决定。 |
| SVG 的 `<title>`/`<desc>` 带属性（`<title id="...">`） | 校验按**标签名**匹配，带属性容易被判 `[SVG-NO-META]`；统一写不带属性的 `<title>`/`<desc>`（`svg-maker` 模板已同步加注）。 |
| SVG 根元素写了 `width`/`height` | 与同目录其它资产写法不一致，统一只保留固定 `viewBox`。 |
| 长链 / 带分叉的流程仍用 mermaid，观感差被要求重画 | 命中复杂度阈值（节点 ≥12、含分叉汇合分区、纵向分层）一律用 SVG：见 [writing-guide.md](writing-guide.md)「图表约束」。 |
| 小节里只有一张图、没有正文 | 图前补导读段、图后补"该看什么"；只有图会被 `[FIGURE-ONLY]` 提示。 |
| 手绘 / 子代理产出的 SVG 看着对、边连错了 | 跑 `scripts/audit-svg-topology.mjs` 打印「起点 → 终点」与期望清单核对；这是唯一能程序化发现该错误的手段。 |
| 用 rsvg 预览 SVG 全黑，误以为图坏了 | SVG 用 `var()` + 暗色适配，librsvg 不解析自定义属性；用 `scripts/render-svg-preview.mjs` 先展平字面色再出 PNG。 |
| 重排章节后小节编号重复、交叉引用失效 | 跑 `scripts/scan-narrative.mjs`（`[HEADING-SEQ]` / `[XREF-DANGLING]`）；重排脚本不要用"只替换首位数字"的正则。 |
| 量化指标没有实测数据，于是编造或只写"缺失" | 走三档口径：实测 / 可校准口径模型 / 显式不可复原（见 [quantification.md](quantification.md)）。 |
| 把未完成项写成"刻意的设计选择" | 欠账一律落在「已知边界 / 开放问题」；叙述型的设计输入必须分级（证实 / 推断 / 不可复原）。 |
