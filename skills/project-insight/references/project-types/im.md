# im 类型规格（im）

> 适用于：即时通讯 / 消息系统 / 聊天 / 长连接网关 类项目。
> 判定信号见 [../dimension-triggers.md](../dimension-triggers.md)「类型判定与分流」；本规格在通用默认规格（[_default.md](_default.md)）基础上**追加** im 特有要求，不得放宽通用铁律（真源验证 / mermaid 校验 / kb_repo 判定 / 增量铁律 / 写作规范 / 质量红线 / 索引同步 / 规模门控 / 数据模型探测）。可叠加：framework（协议/网关 SDK 化时）。

## 固定结构块（硬规格）

### 产出形态

通用产出形态 / 分文件判定 / 信息密度分配 / 索引约定见 [_default.md](_default.md)，本规格仅追加 im 特有要求：

- 多关注面 → `README.md` + 子文档。
- 必拆子文档候选（命中并够深才拆，主题语义命名、无 `01-` 序号前缀）：
  - `protocol.md`：通信协议（帧格式、握手、ACK、加密）
  - `gateway.md`：长连接网关（连接管理、粘滞、心跳、断线重连）
  - `store.md`：消息存储（消息表设计、离线消息、时序与幂等、检索）
- 拆出子文档后按其索引约定回写（见 `_default.md`）。

### 信息密度分配

- 承接 `_default.md` 的 README 概览口径；README 架构总览侧重完整业务链路（Client → Gateway → Message Service → Store）。
- 子文档承载协议、网关、消息存储等深度关注点；每篇满足通用四要素（核心结构/执行流程/设计决策/依赖）+ `文件:行号` 真源引用，且每篇至少 1 张属于本关注面的核心链路图。

## 必含要素块（硬规格）

在通用必含要素清单（`_default.md`：根因 / 概览 / 架构 / 链路 / 深挖 / 全局关联 / 真源引用）之外，im 类**必须**额外覆盖以下硬规格；可放任意标题任意顺序，顺序交给叙事主线，但逐项齐全才算完成：

- **连接 / 会话生命周期**：连接建立 / 鉴权 / 心跳 / 断开 / 重连——用 `sequenceDiagram` 或 `stateDiagram-v2` 承载完整生命周期，不写纯文字长段。
- **消息链路**：单发 / 群发、离线消息、消息时序与幂等、投递确认（ACK）。
- **消息存储与检索**：消息表设计、session/unread、存储演进（从内存到分库/分表/冷热分层）。
- **跨模块时序**：长流程配 `sequenceDiagram` 体现完整业务链路（Client → Gateway → Message Service → Store 的一次消息收发闭环），而非单模块局部流。

每篇子文档满足通用四要素 + `文件:行号` 真源引用。

## 自由纵深块（软区）

- 「值得学什么」落点：长连接网络的容错（心跳 / 超时 / 重连）、消息幂等与顺序、离线消息的存储与推拉权衡、多端同步。
- 常见坑：
  - 只用纯文字长段走连接 / 消息流程——应给 `sequenceDiagram` / `stateDiagram-v2`。
  - 把存储写成纯字段清单（表字段罗列）而非设计——应讲消息表设计的权衡（为什么这样分表、如何支撑幂等与检索）。
  - 只讲单模块局部流，不讲跨模块完整链路。
- 深挖指引：比较不同 im 的消息时序与分发策略（TCP 长连接 vs 推送），提炼可迁移的可靠性设计（如幂等键、投递确认、重连退避）；深度不足标 `[WIP]`/`TODO`，不硬凑。
