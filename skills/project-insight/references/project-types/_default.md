# 通用默认规格（_default）

> 当项目无法判定为任何具体类型，或无需类型特化时加载本规格（判定信号见 [../dimension-triggers.md](../dimension-triggers.md)「类型判定与分流」）。
> 本规格是「类型无关」的通用默认产出，具体类型的规格可在此基础上细化，但不得放宽下述铁律。

## 固定结构块（硬规格）

### 产出形态

- 单关注面 / 单一关注项目 → 单文件 `README.md`。
- 多关注面项目 → `README.md`（概览 + 架构总览 + 核心模块导读表 + 总结）+ 每关注面一篇 `xxx.md` 子文档（主题语义命名，一主题一篇，无 `01-`/`02-` 序号前缀）。
- 禁止把全部内容压进单个 README；README 只作索引/概览，深度内容下放子文档。

### 分文件判定

拆分依据 = 「项目是否有多个可独立成文、且各自够深挖的关注面」，而非代码行数或预计体积（行数只是复杂度的弱代理，最终以关注面为准）：

- 可自然切出 ≥3 个相对独立的关注面，且每个能展开一段带 `文件:行号` 佐证的深度内容 → 必须拆子文档，README 只作索引/概览。
- 反向判断：拆出的子文档每篇都凑不够深度（无 Why/权衡/源码佐证）→ 为了拆而拆，退化为单文件。
- 关注面由「项目类型」驱动（类型触发判据见 [../dimension-triggers.md](../dimension-triggers.md)）与「语言惯用法」两个维度共同决定；命中即候选、浅则并入 README 小节、够深才独立成篇，机制全程一致。

拆出子文档后必须遵守索引约定：README 新增独立「子文档索引」章节一行一条列全全部子文档（`- [\`xxx.md\`](xxx.md) — 一句话定位`），且正文「核心模块导读表」每一行、提到关注面的章节就地给出 `[\`xxx.md\`](xxx.md)` 内链；新增即回写，遗漏视为未完成。

### 信息密度分配

- README 承载：概览、架构总览、核心模块导读表、总结；具体设计/决策深读下放子文档。
- 子文档承载：深度关注点（设计/决策深读），README 内链接跳转。
- 篇幅由关注面与深度驱动，不设行数上限；该拆已拆、无拖沓为准。不为达标压缩有效内容，也不为凑篇幅硬填。

## 必含要素块（硬规格）

通用必含要素清单（逐项齐全才算完成，可放任意标题任意顺序；不绑定标题、不绑定顺序，顺序交给叙事主线）：

- 根因：解决什么根本问题（全篇锚点，防功能罗列）
- 概览：是什么 / 痛点 / 适用场景 + 核心能力清单表 + 技术栈一览表
- 架构：架构总览图（工具按 [kb-repo-rules.md](../kb-repo-rules.md) 选型规则，结构类优先 SVG）+ 模块职责映射(目录树)
- 链路：启动流程 或 请求链路（图承载，非文字长段；命中即给 `sequenceDiagram`/`graph`）
- 深挖：≥1 个按项目特点深入的关注面（Why>What + 权衡），从丰富内容菜单取最突出的 2-4 维，不每维都写。"项目特点"的候选来源 = 被分析项目 README 自述能力点（优先级最高）+ 类型/语言触发判据（见 [../dimension-triggers.md](../dimension-triggers.md)），二者均须经源码探测验证后取交集落地；README 点名的独特卖点不因落在通用模板之外而忽略
- 全局关联：每个模块分析连回整体设计哲学（叙事连贯，避免孤立代码审查）
- 真源引用：≥2 处带 `仓库相对路径/文件.ext:行号` 的代码引用（经程序重定位验证；正文「结论/权衡 + `[路径:行号]`」呈现，不整段贴码）

## 自由纵深块（软区）

- 从丰富内容菜单取子集：概览 / 能力表 / 技术栈表 / 同类对比 / 规模指标 / 架构总览 / 启动流程或链路 / 核心模块导读 / 深度子文档 / 设计亮点 / 不足风险 / 可借鉴设计 / 总结回扣根因（详见 [../writing-guide.md](../writing-guide.md)「丰富内容菜单」）。
- 定维度非全覆盖：选项目特点最突出的 2-4 维深入，不每维都写。定维度的"项目特点"来源 = 被分析项目 README 自述能力点（优先级最高）+ 类型/语言触发判据，二者须经源码探测验证后取交集落地（详见 [../flow-new.md](../flow-new.md)「定维度，非全覆盖」）。README 点名的独特卖点不因落在通用模板之外而忽略
- 深挖方向覆盖「关注面」而非「每节都写」；命中「类型驱动的关注面触发判据」的关注面够深则独立成文、浅则并入 README 小节（触发判据见 [../dimension-triggers.md](../dimension-triggers.md)）。
- 深度不足标 `[WIP]`/`TODO`，不硬凑；深度方法论遵循 [analysis-guide.md](../analysis-guide.md)（Why>What、权衡、叙事连贯、全局关联）。
- 图与引用同目录；每个子文档用主题语义命名（`architecture.md`/`deployment.md`/`data-model.md`/`memory-system.md`/`llm-route-system.md`）。
