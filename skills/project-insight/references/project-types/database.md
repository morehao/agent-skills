# database 类型规格（database）

> 适用于：数据库 / 存储引擎 类项目——关系型（PostgreSQL/MySQL 系）、KV（Redis/RocksDB 系）、时序（InfluxDB 系）、图（Neo4j 系）、OLAP / 列存（ClickHouse 系）、搜索引擎（Elasticsearch 系）、嵌入式存储引擎。
> 判定信号见 [../dimension-triggers.md](../dimension-triggers.md)「类型判定与分流」；本规格在通用默认规格（[_default.md](_default.md)）基础上**追加** database 特有要求，不得放宽通用铁律（真源验证 / mermaid 校验 / kb_repo 判定 / 增量铁律 / 写作规范 / 质量红线 / 索引同步 / 规模门控 / 数据模型探测）。可叠加：framework（提供客户端 SDK / 插件 / 存储引擎 API 时）。

## 固定结构块（硬规格）

### 产出形态

通用产出形态 / 分文件判定 / 信息密度分配 / 索引约定见 [_default.md](_default.md)，本规格仅追加 database 特有要求：

- 必拆子文档候选（命中并够深才拆，主题语义命名、无 `01-` 序号前缀）：
  - `storage-layout.md`：存算布局与数据组织（LSM / B+Tree / 列存 / 分片）
  - `indexing.md`：索引结构（主索引、二级索引、倒排、向量索引）与读写放大
  - `wal-transaction.md`：WAL 与刷盘、事务与一致性模型（隔离级别 / 分布式事务 / MVCC）
  - `replication.md`：分片 / 复制 / 一致性协议（Raft / Paxos / gossip / 主从）
- 拆出子文档后按其索引约定回写（见 `_default.md`）。

### 信息密度分配

- 承接 `_default.md` 的 README 概览口径；README 架构总览侧重整体分层（Client/协议层 → 解析/执行层 → 存储引擎）与写入-读取两条主路径。
- 子文档承载存储布局、索引、事务、复制等深度关注点；每篇满足通用四要素（核心结构/执行流程/设计决策/依赖）+ `文件:行号` 真源引用，且每篇至少 1 张属于本关注面的核心链路图。

## 必含要素块（硬规格）

在通用必含要素清单（`_default.md`：根因 / 概览 / 架构 / 链路 / 深挖 / 全局关联 / 真源引用）之外，database 类**必须**额外覆盖以下硬规格；可放任意标题任意顺序，顺序交给叙事主线，但逐项齐全才算完成：

- **存算布局**：LSM / B+Tree / 列存 / 内存结构的选型与权衡（读放大 / 写放大 / 空间放大），数据如何在磁盘-内存间组织（每条论断带 `文件:行号`；命中「强制图位清单」即给 `graph`/`sequenceDiagram`，如"一次写入从 WAL 到刷盘"的时序，不写纯文字长段）。
- **索引结构**：主索引与二级索引、倒排 / 向量等扩展索引；每个索引在具体 workload 下的取舍（为什么选它、代价是什么），不写成索引教科书。
- **WAL 与刷盘**：WAL 格式与刷盘时机（group commit / fsync 策略）、崩溃恢复路径（redo / undo）、数据页的落盘与 checkpoint。
- **事务与一致性模型**：隔离级别 / MVCC 实现、锁与并发控制（悲观 / 乐观）、分布式事务（2PC / TCC / saga，有则覆盖）或单机 ACID 的取舍。
- **缓存与淘汰**：缓存层次（buffer pool / page cache）、淘汰策略（LRU 及其变体）与命中率权衡。
- **分片 / 复制 / 一致性协议**：数据分片策略、复制拓扑（主从 / 多主 / 无主）、一致性协议（Raft / Paxos / gossip）与脑裂防护、故障转移。

## 自由纵深块（软区）

- 「值得学什么」落点：读写放大三角（LSM vs B+Tree）的具体取舍、崩溃一致性的工程实现（WAL / fsync / 恢复）、一致性协议在工程里的落地细节、缓存与存储的边界设计。
- 常见坑：
  - 索引结构写成教科书（堆结构/复杂度罗列）——应讲在具体 workload 与硬件下的取舍。
  - 不讲崩溃恢复路径（WAL 写了什么、什么时候 fsync、恢复时怎么重放）——这是存储引擎可靠性的核心。
  - 只列特性清单（"支持事务、支持复制"）不讲一致性模型与隔离级别的代价。
  - 不对比同类引擎（如 LSM vs B+Tree 的读写特性差异）的取舍。
- 深挖指引：比较不同存储引擎的存算布局与刷盘策略、不同一致性协议工程实现的差异；深度不足标 `[WIP]`/`TODO`，不硬凑。
