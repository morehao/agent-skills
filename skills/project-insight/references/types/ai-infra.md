# AI 基础设施

## 问题

1. 一次推理请求的端到端路径：接入 → 路由 → 排队 → 调度 → 执行 → 流式返回？
2. 批处理策略：静态/动态/continuous batching？吞吐与延迟如何取舍？
3. KV cache 如何管理：分配、复用、prefix caching、显存回收？
4. 量化与显存：INT8/FP8/GGUF 等选择带来什么精度/吞吐代价？
5. 模型加载与热切换：启动、预热、版本回滚如何做？
6. 向量索引：HNSW/IVF/暴力扫描；召回率、延迟、内存如何三角取舍？
7. RAG 管线：切分 → embedding → 检索 → 重排 → 上下文组装，每步失败如何降级？
8. 多租户与限流：配额、隔离、计费/用量统计落在哪一层？
9. 可观测与评测：吞吐、首 token 延迟、错误率、成本；eval 如何进 CI？
10. 调度与抢占：超时、优先级、公平性如何保证？
11. 缓存策略：结果缓存、语义缓存、embedding 缓存，何时失效？
12. 成本模型：单位请求成本由哪些参数决定？最容易被低估的是什么？

## 典型决策

- continuous batching vs 静态批；
- 自建推理 vs 托管 API；
- HNSW vs IVF vs 暴力（召回/成本）；
- 先检索后重排 vs 直接检索；
- 单模型 vs 路由到多模型。

## 常见坑

- 只写"用了什么模型/框架"，不讲吞吐、延迟、成本三角；
- 把向量库写成参数清单，不讲 workload 下的索引取舍；
- RAG 只列步骤，不讲每步失败模式与补偿；
- 用单一延迟数字，不分首 token/总时长、p50/p95；
- 没有评测集，无法判断优化是否真的有效。
