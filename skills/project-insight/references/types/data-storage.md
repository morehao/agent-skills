# 数据 / 存储

## 问题

1. 数据如何组织：行存/列存、LSM/B+Tree、页式/日志式？为什么？
2. 一次写入的完整路径：入口 → 日志 → 内存 → 持久化，何时算"已提交"？
3. 一次读取的完整路径：缓存 → 索引 → 数据页，命中/未命中分别怎么走？
4. WAL 写了什么、何时 fsync、崩溃后如何恢复？checkpoint 何时发生？
5. 索引结构：主索引、二级索引、倒排/向量；各自在什么 workload 下值得？
6. 事务与并发控制：隔离级别、MVCC、锁粒度、乐观/悲观？
7. 缓存层次与淘汰策略：buffer pool、page cache、LRU 变体；命中率与内存如何取舍？
8. compaction / 垃圾回收如何工作？写放大从哪来？
9. 复制与分片：主从/多主/无主、一致性协议、脑裂防护、故障转移？
10. 查询如何执行：解析 → 计划 → 执行 → 结果；优化器做了哪些取舍？
11. 数据如何演进：迁移、兼容、回滚、在线变更？
12. 故障域在哪：单机、磁盘、网络、机房分别如何降级？

## 典型决策

- LSM vs B+Tree（写放大 vs 读放大）；
- WAL + 内存表 vs shadow paging；
- 悲观锁 vs 乐观并发；
- 主从异步复制 vs Raft/Paxos 同步复制；
- 内置索引 vs 外部搜索引擎。

## 常见坑

- 把索引结构写成数据结构教科书，不讲 workload 与硬件；
- 不讲崩溃恢复路径（这恰是存储引擎可靠性的核心）；
- 只列"支持事务/复制"，不讲隔离级别与一致性代价；
- 把性能数字当结论，不给数据集与硬件条件。
