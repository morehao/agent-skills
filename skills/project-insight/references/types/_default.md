# 通用提问清单（_default）

> 判不出具体类型，或只需要通用问题集时使用。挑 8–10 个最相关的，不要逐条填表。

## 问题

1. 系统边界在哪？什么在系统内，什么交给外部？
2. 一个请求/任务从进入到返回，经过哪些部件？
3. 状态存在哪？谁是真相源？缓存与持久化如何分工？
4. 允许的依赖方向是什么？哪些依赖被刻意禁止？
5. 并发模型是什么？共享什么、隔离什么？
6. 失败如何传播、重试、降级、恢复？
7. 扩展点在哪？用户/插件代码如何注入、何时被调用？
8. 配置从哪来？不同部署形态如何隔离？
9. 数据与协议如何演进？兼容与迁移策略是什么？
10. 信任边界在哪？认证、授权、租户隔离落在哪一层？
11. 可观测性靠什么？出问题时先看什么？
12. 哪些设计是为规模/性能做的，哪些是为简单性做的？
13. 哪些约束是外部的（部署/合规/团队），哪些是历史包袱？
14. 如果重来一次，作者最可能改哪一处？
15. 哪些能力是 README 宣传但源码支撑不足的？

## 典型决策

- 单体 vs 拆分、进程内 vs 跨进程、同步 vs 异步；
- 状态放哪、谁拥有写权限；
- 扩展点用接口、事件还是配置；
- 失败重试与幂等的边界；
- 抽象层放在哪一层、为什么不再多一层。

## 常见坑

- 用目录结构代替架构；
- 只写 What 不写 Why；
- 把"非主流"当"错误"，不问约束；
- 把未完成项包装成"刻意设计"。
