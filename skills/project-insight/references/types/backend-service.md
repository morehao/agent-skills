# 后端服务 / 网关

## 问题

1. 边界画在哪：哪些能力在服务内，哪些推给数据库、缓存、消息队列、模型或宿主？
2. 一次请求的完整生命周期：接入 → 鉴权 → 路由 → 业务 → 存储 → 响应？
3. 鉴权发生在哪一层？连接级、请求级还是业务级？权限变更如何生效？
4. 状态是什么？会话、连接、任务状态分别存在哪？谁是真相源？
5. 同步调用与异步消息的边界在哪？为什么这里用队列、那里直接调？
6. 多租户如何隔离：库、表、行、连接池还是进程？
7. 配置从哪来？不同部署形态（单机/集群/云）如何装配？
8. 失败如何传播：重试、超时、熔断、降级、幂等键分别放在哪？
9. 背压与限流在哪一层？超载时先牺牲什么？
10. 可观测性靠什么？一次失败请求如何定位到具体一跳？
11. 协议/接口如何演进？旧客户端怎么办？
12. 扩展点在哪：中间件、插件、钩子还是事件？

## 典型决策

- 鉴权前移 vs 每请求校验；
- 有状态会话 vs 无状态令牌；
- 单体进程内调用 vs 拆服务；
- 同步 RPC vs 事件/队列；
- 共享库 vs 独立服务；
- 连接级 vs 请求级限流。

## 常见坑

- 把"用了某框架"当架构；
- 只画请求主路径，不画失败/超时/重试；
- 权限只写前端显隐，不写后端校验与数据范围；
- 把部署形态当细节，导致边界与一致性判断全错。
