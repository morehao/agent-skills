# 前端应用 / Web 客户端

## 问题

1. 边界画在哪：哪些逻辑在浏览器，哪些在服务端/边缘/CDN？为什么这样切？
2. 路由与页面边界：哪些是布局、哪些是页面、哪些是模态/浮层？权限如何挂到路由？
3. 渲染模式是什么：CSR / SSR / SSG / ISR / 流式？选择依据与代价？
4. 状态分几层：URL、服务端缓存、全局 store、组件局部状态？谁是真相源？
5. 数据获取放在哪：路由 loader、组件请求、SSR、还是构建期？瀑布请求如何避免？
6. 鉴权与会话：token 存哪、何时刷新、未登录/过期如何跳转、CSR 闪烁如何避免？
7. 错误与加载边界：error boundary、suspense、骨架屏、重试分别放在哪一层？
8. 性能预算：首屏 JS、路由拆分、图片/字体、缓存策略；哪些是硬指标？
9. 构建与部署：单仓/多包、产物托管、CDN、环境变量如何注入？
10. 设计系统与样式：组件库、主题、样式隔离、暗色模式如何组织？
11. 可观测性：前端错误、性能指标、用户行为如何采集，采样与隐私边界？
12. 扩展点：插件、微前端、iframe、模块联邦？隔离与通信成本是什么？

## 典型决策

- CSR vs SSR/SSG vs 混合渲染；
- 全局 store vs 服务端状态库 vs 局部状态；
- 路由级拆分 vs 组件级懒加载；
- 单应用 vs 微前端/模块联邦；
- 自建设计系统 vs 组件库；
- 客户端鉴权 vs BFF/服务端会话。

## 常见坑

- 把组件树当架构，不讲数据流与渲染边界；
- 只讲"用了某框架"，不讲状态所有权与缓存失效；
- 忽略瀑布请求、首屏 JS 与缓存策略；
- 鉴权只写前端路由守卫，不写服务端校验；
- 把构建工具链当架构，忽略部署形态与运行时边界。
