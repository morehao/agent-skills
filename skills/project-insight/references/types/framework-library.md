# 框架 / 库 / SDK / CLI

## 问题

1. 公共 API 的边界在哪？哪些是承诺，哪些是实现细节？
2. 用户代码在什么时机、以什么方式被调度（中间件链、钩子、插件、生命周期）？
3. 扩展点有几种？它们之间如何组合、冲突时谁优先？
4. 错误模型是什么？错误如何浮现、传播、被调用方识别？
5. 兼容策略是什么：语义化版本、废弃周期、行为变更如何告知？
6. 性能承诺是什么？哪些路径被刻意优化，代价是什么？
7. 依赖策略：零依赖、最小依赖还是借力生态？为什么？
8. 配置与约定的比例：约定优于配置，还是显式配置？
9. 测试策略：契约测试、快照、集成测试各覆盖什么？
10. 文档与示例如何与实现保持同步？
11. 插件/扩展的隔离边界：崩溃、版本冲突、资源竞争如何处理？
12. CLI 额外问：参数解析、配置优先级、退出码、交互模式如何设计？

## 典型决策

- 中间件链（洋葱/线性/管道）vs 直接调用；
- 接口/泛型/反射实现扩展；
- 约定优于配置 vs 显式配置；
- 单包 vs 多包、是否暴露内部类型；
- 同步 API vs 异步/回调/Promise。

## 常见坑

- 把"支持哪些扩展点"列成清单，不讲调度与代价；
- 语言惯用法写成教科书，不落在该框架的设计约束上；
- 只讲 API 形状，不讲兼容与废弃；
- 忽略扩展点之间的边界与组合成本。
