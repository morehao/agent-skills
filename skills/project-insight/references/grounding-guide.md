# 引用与真源校验（引用可选，落盘即验）

> 由 SKILL.md「引用」段与「执行流程主干」step 7（真源校验）按需加载。本文件讲两件事：**什么时候值得给一处引用**，以及**引用一旦写进文档，如何由程序保证它真实**。

## 一、引用是可选的证据，不是覆盖率指标

解读的主体是叙述与判断：这个项目解决了什么、架构怎么组织、为什么这样权衡。这些内容靠动笔前读源码、靠讲清理由来成立，不需要每句都挂行号。

判断"要不要给这处引用"只问一句：**删掉它，读者会不会误以为我在编？**

值得给（满足任一）：

- **反直觉 / 易被质疑的结论**——读者第一反应是"真的吗"；
- **具体数字、阈值、默认值、上限**——且数字来自源码常量或配置；
- **安全 / 权限 / 数据一致性 / 兼容性边界**；
- **用户指定要核验的点**，或这是读者最想深挖、又不容易在源码里找到的入口。

不必给（满足任一）：

- 架构分层、模块职责、目录映射——图与目录树已经表达；
- 流程步骤、时序——图承载，文字只补叙；
- 权衡、对比、评价、可借鉴——这是**判断**，要的是理由不是行号；
- 同一结论已在前文给过出处——不重复；
- 只是"证明我读过源码"的装饰性引用。

**整篇零引用是合法产出**：`verify-references.mjs` 对无引用文档直接通过，这不是漏检；取代它的是写作时的源码核对与成稿抽查（见 SKILL.md 质量红线「关键论断已抽查」）。

## 二、思想

模型给的行号是**猜的**，但从上下文**原样复制的锚点行是可信指纹**。与其信行号，不如把锚点行当线索去真实源码里按位置校验、再搜索定位，算出真实行号。程序负责验证，不让模型自证。

## 三、写出来的引用必须满足的约束

- 引用路径用**仓库相对路径 + 行号**：`模块/子目录/文件名.ext:行号`（如 `pkg/utils/util.go:42`；后缀按项目语言替换，如 `.ts`/`.py`/`.rs`）；禁止裸文件名。
- 引用链接留空括号 `[path:start-end]()`，由程序统一补成真实 URL + 行锚点；落库前须经程序重定位，用真实行号覆盖模型行号。
- **同一结论只给一处代表性位置**，不在同一段堆多处；同一主题后文不重复给。
- **定位失败不允许静默放过**：找不到匹配的引用必须保留原样并追加 `[UNVERIFIED]` 标记，在文末汇总列出，交由人工复核，不能与已验证引用长得一样。

### 引用展示与指纹分离（防"正文贴码"）

`锚点行` 只在程序内做真实源码重定位，**默认不进入文档正文**。正文里每处引用统一呈现为「一句结论 + `[路径:start-end]` 标点」，不复制整段代码：

```
Gateway 把"连接为什么失败"变成可观测：close 时把 `closeCause`/`phase`/`lastFrameType` 全部带进日志 close context（`src/gateway/server/ws-connection.ts:486-505`）。
```

完整实现细节交给读者点开 `[路径:start-end]` 的源码锚点即可。仅当 **该段代码本身就是不可绕过的设计载体**，且用户明确要求贴码时，才允许放**精简片段**（只取不可绕过的核心，不整段照搬），孤立的 `> [path] — 整段代码` 引用块列为违规。

### 指纹块（Grounding fingerprint）——首末行双锚点，不整段贴码

为使程序精确校验行号，**每处展示引用**后应紧邻一个**不进入正文渲染**的指纹注释（常规做法；省略时脚本只能降级弱校验，无法发现行号偏差）。**指纹只取引用区间的首行 + 末行两行原文**——指纹是定位依据，不是展示素材：

```
[path:start-end]() 一句结论
<!-- anchor: 区间首行原文（逐字复制，≤1 行） … 区间末行原文（逐字复制，≤1 行） -->
```

- **锚点行必须从源码上下文逐字复制**（不得改写、不得凭记忆拼），只作程序定位用、不进入正文；从行首起截断 ≤80 字符，行首空白可去掉。
- 单行区间 `[x-x]` 只需一行锚点；区间较短时首末锚点允许相同。
- 锚点须为**有辨识度的一行**（≥6 字符且含字母/数字）；纯括号、纯空白等平凡行取区间内最近的非平凡行作锚点。
- 锚点行含 `--` 等破坏 HTML 注释的字符时改用 base64 形式：`<!-- anchor-base64:<首行 … 末行 的 base64> -->`。
- 程序读取该注释 → 在真实源码里做**双向精确校验**：第 `start` 行附近以首锚开头、第 `end` 行附近以末锚开头（各容 ±2 行，容忍平凡行取相邻非平凡行）；位置校验失败则全文件搜索锚点算出真实行号，输出 `[GROUNDER-OK/MISMATCH]`。
- 定位失败时脚本输出 `[GROUNDER-UNVERIFIED]`，与正文标 `[UNVERIFIED]` 对应，文末汇总供人工复核。
- 旧格式 `<!-- snippet: … -->` / `<!-- snippet-base64: … -->` 仍被脚本支持（存量文档无需迁移），新产出一律用锚点格式。

## 四、核心实现（已有可运行工具，原理简述）

> 真源重定位已由 `scripts/verify-references.mjs` 落地，输出 `[GROUNDER-OK/WEAK/MISMATCH/UNVERIFIED/TRAVERSAL]` 五态并控制退出码，内嵌路径防穿越。核心原理如下（跨语言可迁移，脚本即按此实现）：
>
> - **定位（锚点）**：锚点行是可信指纹——先在声称行号处做精确位置校验（第 `start` 行附近以首锚开头、第 `end` 行附近以末锚开头），失败再全文件搜索锚点算出真实行号；仍失败则显式置为未验证。
> - **覆盖**：定位成功用真实行号覆盖模型行号；失败显式置为未验证（对应 `[UNVERIFIED]`），不静默放过。
> - **防穿越**：`realpath` 消除 `../` 与符号链接，再校验目标仍在仓库根内（`commonpath`/公共前缀）——防止 `../../etc/passwd` 一类任意文件读取。此校验同样适用于对 `kb_repo` 的任何读写。

**教训**：若解读走 RAG（代码量大的仓库），切分时给每个 chunk 记录真实起始/结束行号（切分器对每个 chunk 独立复制 `meta_data`），否则后续落点无据可依。

## 五、收尾校验（脚本用法统一出处）

落盘前对**含引用的产物 md** 跑校验；任一非 0 退出码视为未通过（无引用的文档会自动通过）：

```bash
# 在 skill 的 scripts/ 目录下（依赖 mermaid + jsdom，首次需 npm install）
# 第一个参数 <source_repo> = 源码仓库根；它必须是「本次选定基线的工作树」（见 version-baseline.md），
# 不是知识库仓库 kb_repo（解读 md 落哪儿与校验读哪儿是两回事），也不是随手一个 HEAD。
node scripts/verify-references.mjs <source_repo> <解读.md>...   # 代码引用：五态输出，MISMATCH 覆盖行号、UNVERIFIED 标记保留、TRAVERSAL 必须修复
node scripts/verify-references.mjs --diff <source_repo> <解读.md>...   # 增量预检：输出 STABLE/STALE/UNRESOLVED 清单 + 汇总；全 STABLE 退出码 0
node scripts/verify-references.mjs --stats <解读.md>...         # 引用密度自查：每篇引用数、每千字密度、单段多引用的段落（只报告，不阻断）
node scripts/check-mermaid.mjs <解读.md>...                  # Mermaid 图：任一 [MERMAID-ERROR] 修复至全 OK，[MERMAID-WARN] 收敛为 0
```

产出 `architecture-design.md`（叙述型架构设计说明）时，**追加**一个：

```bash
node scripts/scan-narrative.mjs [--repo-root <解读目录>] <architecture-design.md>...
# 叙述型核实：零代码索引 / 零跨文档引用 / <details> 内不得藏索引 / 引用的 SVG 存在且自包含 / 有图 / 取舍章节提到代价
# 该文档不进 verify-references.mjs 的引用统计（零引用是预期行为，不是漏检）
```

> 脚本内部与输出里沿用了历史参数名 `kb_repo`，**语义就是源码仓库根（`source_repo`）**——解读产物仍落在 `kb_repo`（知识库仓库），两者不要混。

> `--diff` 用于增量动笔前：把现有解读引用的真实状态（STABLE / STALE 带真实
> 行号 / UNRESOLVED）作为增量差异依据与 noop 止损输入；文档没有引用时以
> `git diff` / release notes 为主（完整流程见 flow-incremental.md）。

- 依赖 `mermaid`、`jsdom`（`node_modules` 被 gitignore，不入库）；本机若用 `cp -r` 复制注册而非软链，复制后要在副本的 `scripts/` 重装。
- 校验用 node 直跑（不是打包器）。
