# 更新模式：已有 wiki 随上游版本演进

> 由 SKILL.md「执行流程主干」的 step 2（模式判定）判定为**更新模式**时按需加载。
> 本文件承载：**更新的触发条件、五条铁律、diff 两端、受影响页与未覆盖变更面怎么算、
> 重写授权与非阻断护栏、noop、收尾与残余风险**。

## 触发条件（版本事件驱动，不是巡检）

- **基线升级**：上游出现新 tag / release（`scripts/select-baseline.mjs` 选出的新 ref 与契约行不同）；
- 或**用户显式要求**（"上游发新版了，更新一下""这页补充得更深一些"）。

**不做默认分支巡检**：文档不会因为上游 `main` 动了几个提交就自动过期重写。
代价要明说——两个 tag 之间的能力变化不会进入文档；活跃但发版稀疏的项目，wiki 会滞后。

> 与 project-insight 的分工：那边的保真对象是**证据链**（每条引用能否重定位），
> 这边的保真对象是**读者认知模型**（页集是否还覆盖得住、叙述是否还对）。两边不可互相照搬。

## 铁律（违反即重来）

1. **先读现有文档，再动笔。** 不先读就改 = 失败。
2. **差异驱动。** 每处变更必须能追溯到上游 diff / release notes（拿不到则按声明的代码快照比对）。找不到依据的改动不做。
3. **先确认现有覆盖范围。** 先定位现有文档已覆盖的内容，避免重复；变更只落在它该落的地方。
4. **页身份稳定。** 页文件名与页标题**不动**；删除、合并、改名必须由用户**明确确认**。
5. **页集合只增不删。** 新增页允许；收缩页集合是读者的路径变更，不是作者的一时方便。

> 这五条与 project-insight 增量的"STABLE 章节原文保留"**故意不同**：那边产物是逐条独立的证据条目，
> 就地打补丁无损；这边产物是**面向读者的连贯散文**，段级打补丁会毁掉叙述流。
> 所以本 skill 的保真单位是**页**，不是段——但"不得静默丢弃"这条底线不变（见下方护栏）。

## 两端与 diff

| 端 | 来源 |
|----|------|
| 旧 | 首页 `README.md` 的契约行（`**本文档依据**：…`，见 [version-contract.md](version-contract.md)） |
| 新 | `scripts/select-baseline.mjs` 本次选定的 ref（陈旧 / 歧义同样走三选一裁决） |

拿到两端后跑 `git diff --name-only <旧ref>..<新ref>`，再用预检脚本把机器能算的部分算出来：

```bash
node scripts/plan-update.mjs <docs-dir> --source-repo <repo> --from <旧ref> --to <新ref> [--emit <快照>]
node scripts/plan-update.mjs <docs-dir> --against <快照>
```

契约行缺失时退化为代码快照比对，并在产物与交付清单里显式声明（见 [version-contract.md](version-contract.md)）。

## 受影响页判定（哪些页必须复核）

**受影响页 = 页内依据行的路径 ∩ 变更文件。** 用**产物态的依据行**（章末 `> 依据：…`，
它已被门禁校验过），不要用首页索引表里的"依据文件"列——那一列是规划态，没有校验。

其中有一条**可证明**的结论，它是整套机制的地基：

> 若某页的全部依据行路径在两个 ref 之间**内容逐字相同**（diff 未触及该文件），
> 那么该页的依据行在新基线上**依然成立**——同路径、同内容，行号不可能变。

因此"**未受影响页不动**"是正确的决定，不是偷懒。精度分两级：

| 级别 | 判据 | 强度 |
|------|------|------|
| 文件级 | 路径是否出现在 `git diff --name-only` 中 | **确定**：不出现即可证明仍成立 |
| 行级 | 依据行区间 ∩ `git diff` **旧侧**变更块 | **粗但确定**：相交即要求复核（`[DOC-UPDATE-TOUCHED]`），不相交不报 |

行级只给粗信号是明确取舍：依据行区间通常偏宽，命中率偏高，宁可多复核也不要漏。
粗但确定，远胜精细但静默。

**第二张清单：未覆盖的变更面**（对应 [page-plan.md](page-plan.md) 说的头号毛病"遗漏"）：

- 变更中**新增**的文件 / 目录 / 模块，未被任何页的依据行覆盖；
- 叠加 `README` / `CHANGELOG` / 依赖清单 / 部署文件的变化（这几类是"能力声明"与"运行方式"的入口）。

产出 `[DOC-UPDATE-UNCOVERED]`——"**可能要加页**"的候选。两张清单合起来就是本次更新的规划输入。

## 允许整页重写

对**受影响页**，允许整页重写，含小节（`##` / `###`）的增删与重排。理由：wiki 的产物是给读者读的
连贯叙述，版本升级往往改变的是**讲述方式**，而不是往段落之间插句子。

分层规则：

- **页身份**（`README.md` 与各页文件名、页标题）= 读者的路径与首页索引的锚，稳定；
- **页内容**（小节结构、图、表、散文）= 可以重写；
- **新增能力优先写进已有页**并就地重排；确实撑得起一页才新建页（页数由内容决定，不凑数，
  见 [page-plan.md](page-plan.md)）。

## 非阻断护栏：收缩必须显形、删减必须交代

重写授权换掉了"结构保护"，所以护栏从"阻止"改为"**显形**"。预检脚本用**前后两次结构指纹比对**：

- 改写**前**：`--emit <快照>`（快照默认落系统临时目录，**不进产物目录、不进源码仓**）；
- 改写**后**：`--against <快照>`。

指纹 = 每页的 `{标题集合、依据行集合、图表数、正文有效行数}`，比对后产出：

| 输出码 | 档 | 含义 |
|--------|----|------|
| `[DOC-UPDATE-SHRUNK]` | note | 结构指纹收缩：**标题被删、依据行变少、图变少**任一命中即报；正文有效行数**降幅 >25%** 才报（避免正常编辑的噪声） |
| `[DOC-UPDATE-PAGE-DROPPED]` | note | 页集合收缩（页消失） |
| `[DOC-UPDATE-TOUCHED]` | note | 依据行区间与变更块相交，该页须复核 |
| `[DOC-UPDATE-UNCOVERED]` | note | 未被任何页覆盖的变更面 |

**全部是 note，不阻断**（`plan-update.mjs` 本身也不进门禁退出码，见 [grounding-light.md](grounding-light.md)）。
代价由一条流程义务偿还：

> **每一处删减都必须在交付清单里逐条给出理由**（删了哪个标题 / 哪条依据行 / 哪张图，为什么）。
> 这是 project-insight「演进说明」在本 skill 里的对应物——**落在交付清单，不进正文**。
> 只有当"不做什么"本身对读者重要时，才写进「现状与边界」。

## noop

无新基线且用户未要求 → **不动**。不写"已核对至某处"之类的记录（那是双基线模型的产物，
本 skill 只记当前基线），不维护 `CHANGELOG.md`。

## 收尾

1. 更新首页契约行（新 ref + 短 SHA + 日期，格式见 [version-contract.md](version-contract.md)）；
2. 对新基线**全量重跑** `check-all`：`--source-repo` 指向新基线工作树，并传 `--expect-baseline`。
   未受影响页可证明安全，但门禁照跑一遍——受影响页必须在新基线上完整重验，不能只跑改过的那几段；
3. 交付清单必须包含：
   - **逐条回应每一条 note**（含 `DOC-BASELINE-*` / `DOC-SRC-BASELINE-MISMATCH` / `DOC-UPDATE-*`）：
     命中页 + 处置（已改 / 无需改 / 转用户决定）。这条是**流程义务，故意不设程序检查**——
     门禁要求人填写无法验证的字段，只会得到形式填报；
   - 删减项与理由；
   - KB 模式下将改动的索引文件（见 [landing.md](landing.md)）；
4. **只落盘，不代为 `git add/commit/push`**。

## 残余风险（明说）

允许整页重写 + 全部新增检查不阻断，意味着"**更新时静默丢内容**"的防线是
"**显形 + 作者交代 + 用户复核**"，而不是程序阻断。内容是否真的没丢，最终要由**读过旧版的人**判断；
程序只能把变化摆到桌面上。

这是明确的代价，换来的是：不会因为流程字段没填而返工，也不会催生"为了过关而填"的形式合规。
