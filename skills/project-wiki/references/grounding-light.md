# 轻量真源：真实性怎么保证，以及放弃了什么

> 由 SKILL.md「铁律 5」与 step 5（校验）按需加载。
> 本文件是**有意取舍的说明书**：先说清读者看不到什么、程序检查什么、放弃了什么精度。

## 立场

project-insight 用"把证据堆进正文"来保证真实性：每条论断后跟 `文件:行号`，
再跟一行从源码逐字复制的锚点指纹，程序据此精确定位行号。

**这套机制有效，但代价是产出物被代码和校验痕迹淹没**，读者被限定在"能读源码的人"里。

本 skill 换一条路：**校验留在作者侧，正文保持干净**。

| | project-insight | project-wiki |
|---|---|---|
| 引用位置 | 每条论断后紧跟 | **章末聚合成一行** |
| 校验痕迹 | `<!-- anchor: … -->` 进正文 | **不进正文** |
| 出处形态 | `[path:start-end]()` 链接语法 | `` `path:start-end` `` code span |
| 校验方式 | 锚点指纹 + 双向精确重定位 | 路径存在 + 行号在文件范围内 |
| 能发现 | 行号偏移（±N 行） | 编造路径、离谱行号 |
| 读者 | 能读源码的工程师 | 不读源码的广泛读者 |

**这是取舍，不是退化。** 精度换来的是可读性；代价要明说，不能假装不存在。

## 依据行

格式：

```markdown
> 依据：`internal/gateway/router.go:112-168`、`internal/gateway/middleware.go:45-90`
```

- 放在**章节末尾**，聚合该章结论的出处；不要每句后面挂一个。
- 用 code span，**不要写成链接** `[path]()`——产物不做外链解析，也不需要渲染服务。
  （这只约束链接写法，不约束表达手段：图照样是主要手段，见 [diagrams.md](diagrams.md)。）
- 路径为**相对源码仓库根**的相对路径，禁止裸文件名。
- 行号区间用 `start-end`，单行用 `start`。
- 每页行内引用（正文中的 `` `path:line` ``）**≤5 处**；超出会报 `[DOC-INLINE-REFS]`，
  提示把出处收进依据行。
- 依据太长可以**折成多行**，每行都以 `>` 开头（构成同一个引用块）即可；程序把整块都算作依据，
  不会把续行误判成行内引用。

### 别让非引用的值长得像引用

**任何 code span 只要形如 `路径:数字`，就会被当成引用去校验**。写不是引用的内容时避开这个形状：

| 会误报的写法 | 误报 | 怎么改 |
|--------------|------|--------|
| `` `anthropic.claude-3-sonnet-20240229-v1:0` ``（Bedrock 模型标识） | `[DOC-SRC-MISSING]` 路径不存在 | 把版本后缀 `:0` 拆成单独 code span，或整段不用 code span |
| `` `localhost:8001` `` | `[DOC-SRC-MISSING]` 路径不存在 | 写成 `` `:8001` `` 或不用 code span |

反过来，**真实路径要主动写成这个形状**才有校验：`src/app/[owner]/[repo]/page.tsx:111-134`
这种带动态路由方括号的路径是支持的，不写行号则等于没校验。

## 程序检查什么

```bash
node scripts/check-all.mjs <输出目录> --source-repo <源码根>
```

| 检查 | 输出码 | 拦住什么幻觉 |
|------|--------|-------------|
| 依据行/行内引用的路径真实存在 | `[DOC-SRC-MISSING]` | 编造文件路径（最常见） |
| 行号落在该文件行数范围内 | `[DOC-SRC-ORANGE]` | 编造行号、越界区间 |
| 引用的行号区间首末有序 | `[DOC-SRC-RANGE]` | `100-20` 这类笔误 |
| 引用路径未越出源码根 | `[DOC-SRC-TRAVERSAL]` | `../` 逃逸 |
| 疑似引用但解析不出 | `[DOC-SRC-UNPARSED]` | 换个写法绕过校验（**不静默放过**） |
| 有引用却没传 `--source-repo` | `[DOC-SRC-UNCHECKED]` | "没校验却当成校验过了" |
| 正文出现校验痕迹 | `[DOC-TRACE]` | 锚点指纹/`Sources:` 混进读者视野 |
| 行内引用密度 | `[DOC-INLINE-REFS]` | 出处没聚合，阅读被打断 |
| Mermaid 真解析（flowchart 额外 render） | `[MERMAID-ERROR]` | 渲染报错的图 |
| 代码预算 | `[DOC-CODE-HEAVY]` / `[DOC-CODE-LONG]` | 文档退化成代码堆 |
| 首页索引与实际文件一致 | `[DOC-INDEX-*]` | 索引指向不存在的页 / 页面漏列 |
| 标题数字前缀、缺图、图过复杂、篇幅过短 | `[DOC-HEADING-NUM]` / `[DOC-NO-FIGURE]` / `[DOC-FIGURE-COMPLEX]` / `[DOC-THIN]` | 结构失范 |

### 写法变体会被归一化，不会被跳过

校验前先做轻量归一化，避免"换个写法就绕过"：

| 你写的 | 归一化为 |
|--------|---------|
| `internal/x.go：12`（全角冒号） | `internal/x.go:12` |
| `internal/x.go#L12` / `#L12-L20` | `internal/x.go:12` / `internal/x.go:12-20` |
| `internal/x.go:L12-L20` | `internal/x.go:12-20` |
| `internal/x.go:12–20`（en/em dash） | `internal/x.go:12-20` |

归一化之后仍解析不出的，报 `[DOC-SRC-UNPARSED]`，**不会当作"没有引用"悄悄跳过**。

> 最后这三条（`UNPARSED` / `UNCHECKED` / 归一化）是本 skill 特意保留的**反静默**机制。
> 与其"只校验我能识别的、认不出就当他没说"，不如把认不出的也报出来。
> 这正是 project-insight 现行校验器的坑（它的正则漏掉了自己文档示例里的引用写法，
> 导致通篇编造行号的文档也能"校验通过"），本 skill 不再重犯。

**它检查不了什么（明确声明）**：不校验"这段话与那段代码语义是否吻合"。
那需要人读、或者回到 project-insight 的锚点机制。本 skill 的选择是：
把机器能确定性地验的东西验掉（路径、范围、渲染、结构），
剩下的靠**作者动笔前真的读过源码**——所以流程里"探索"必须在"写作"之前，不能跳。

## 不可编造清单

以下内容一律**不得凭空写出**，无据则删：

- 文件路径、目录结构、行号
- 版本号、发布日期、依赖的具体版本要求
- 性能数字（QPS、延迟、吞吐、内存占用）、容量上限、扩缩容阈值
- 用户量、Star 数、采用者名单
- 路线图、未发布特性、"下一个版本会支持"
- 许可证条款细节（要看 `LICENSE` 原文）
- 与他人/同类项目的对比结论（要有依据，不能凭印象）

## 不确定时的表述

允许的两条路，**不允许第三条**：

1. **去核实**：读源码、读配置、读官方文档，把不确定变成确定。
2. **删掉**：这个信息对读者不关键，就别写。

❌ 不允许：用"可能 / 大概 / 通常 / 一般来说 / 应该"把没核实的事糊过去。
含糊表述在文档里等于把风险转嫁给读者，比直接不写更糟。

如果某个不确定的点**对读者确实关键**（例如"是否支持水平扩展"），
就按第 1 条去源码里找答案；找不到答案就写进「现状与边界」并**明说文档未能确认**——
承认不知道，比编一个答案诚实得多。

## 基线

行号只在确定的快照上成立。动笔前先定基线：

```bash
node scripts/select-baseline.mjs <本地路径|远端URL> [--ref <ref>]
```

稳定 tag > 稳定分支（`release*`/`stable*`/`maintenance*`/`1.x`）> 默认分支。
选定结果写进首页一行：`**本文档依据**：<ref>（<短SHA>），<日期>`。
用户显式指定 ref 时以用户为准，并声明"按用户指定 ref 撰写，非稳定版"。
