# 图表规范

> 由 SKILL.md「执行流程主干」的 step 5/6 按需加载。图是本 skill 的**主要表达手段**，
> 不是插图。约定：能用图说清的，不用文字长段。

## 铁律

1. **凡有形状必给图**——架构、请求链路、时序、状态流转、实体关系，命中即给图。
2. **每张图都要有导读与着落**：图前一句"这张图是什么"，图后一句"该看什么 / 代价是什么"。
   孤零零一张图不算表达，算插图。
3. **图必须真渲染通过**：落盘前跑 `scripts/check-all.mjs`，`[MERMAID-ERROR]` 必须为 0。
   可渲染与否是**程序判定**，不是模型自认为没问题。
4. **一张图只画一件事**：内容太多就拆成两张并各自标注主题，不要贪图单图完整。

## 选型：Mermaid 优先

本 skill 默认用 **Mermaid**（纯文本、可 diff、可维护）。只有下面这四种情形才升级为 **SVG**：

| 情形 | 用什么 | 为什么 |
|------|--------|--------|
| 时序、线性流程、简单拓扑（≤8 节点、无交叉） | **Mermaid** | 自动布局够用，文本易维护 |
| 结构/分层/部署/拓扑（位置本身是论据） | **SVG** | 自动布局不认"谁在底层、边界在哪"，加一个节点就全图重排 |
| 映射、对比（左右同构对齐） | **SVG** | 需要人工对齐 |
| 带回边的状态机 | **SVG** | 自动布局会把回边绕远、标签压在连线上 |
| 节点 ≥12，或含分叉/汇合/泳道/分区 | **SVG** | 复杂度阈值，见下 |

**复杂度阈值（程序会提示）**：一张 Mermaid 图节点数 ≥12，或含明显分叉/汇合结构时，
`scripts/check-docs.mjs` 会报 `[DOC-FIGURE-COMPLEX]`，建议改 SVG。

**SVG 生成走 `svg-maker` skill**，不要自绘一套样式。产出的 SVG 必须自包含
（内联样式、无外部字体/图片/JS），放 `assets/` 下，用英文语义名（不用 `01-` 序号前缀）。
结构图新画或重排后跑一次边拓扑审计——"看着对、边连错"只能靠它发现。

## Mermaid 硬约束

### 方向

- 流程/架构图用 `graph TD` / `graph TB`（自上而下）。
- **节点多时不要排成一条横线**：>8 个节点优先上下分组，而不是一路向右。
- 横向 `LR` 只在"确实是左右对照"时用。

### 节点标签

- 每个节点标签 **3-4 个词以内**；超长会挤压整张图。
- 需要两行时用 `<br>` 断行（不要 `<br/>`、`</br>`），且断在语义点。
- 单个标签文本超过 ~40 字符会被提示补 `<br>`。

### 边标签：`graph` 里不要写

- **不要在 `graph` 的连线上写标签**。`A -->|是| B` 这种写法会让 flowchart 渲染**直接失败**，
  报错是 `Could not find a suitable point for the given distance`（不是语法错误，是布局失败，
  所以肉眼读代码看不出问题）。
- **分支条件收进节点文字**：把 `C -->|是| D[跳过该文件]` 改写成 `C --> D[是：跳过该文件]`；
  也可以把条件提到判断节点里，例如 `C{单文件是否过大}`，两个分支就自明了。
- 实测结论：**判断节点（`{...}`）本身没问题，触发失败的只有边标签**；
  `sequenceDiagram` 也不受影响——它的分支用 `alt` / `loop` 表达。
- 复现只要三行：随便写个 `A[起点] -->|走这条| B[结果]` 跑一次 `check-mermaid.mjs` 即可确认，
  不用拿整篇文档反复试。

### 时序图（`sequenceDiagram`）

- **所有参与者先 `participant` 声明**，再开始画消息。不声明的话 Mermaid 会自动创建，
  顺序和命名都不受控（程序会报 `[DOC-FIGURE-PARTICIPANT]`）。
- 参与者用别名：`participant C as 客户端`。
- 箭头语义：`->>` 请求/调用，`-->>` 响应/返回，`-)` 异步/单向通知，`-x` 失败。
- 用 `Note over A,B: …` 标注关键判断；用 `alt` / `loop` / `opt` 表达分支、循环、可选。
- 图里不要出现"函数名（文件名:行号）"这类实现坐标——读者不关心，且会撑爆标签。

### 状态图

`stateDiagram-v2`；回边多、或状态 >8 个时改用 SVG。

## 图与代码的分工

- **结构、流程、时序、状态一律进图**，不要写成文字长段再配一句"如上"。
- 图里不放代码；代码只在"这段本身就是不可绕过的设计载体"时进正文，且受代码预算约束。
- 配置项、接口、字段不进图，进表。

## 校验

```bash
node scripts/check-all.mjs <输出目录> --source-repo <源码根>
```

内部会跑 Mermaid 真解析（`mermaid.parse`，flowchart 额外 `render`）与结构类图审计，
并检查代码预算、依据行真实性、索引一致性。任一 `[MERMAID-ERROR]` 都必须修到全 `OK` 才落盘。
依赖 `mermaid` + `jsdom`（位于 `skills/project-insight/scripts/node_modules`，
本 skill 只是薄壳转调，**无需另行 npm install**）。
