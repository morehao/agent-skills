# 页面骨架与必答问题

> 由 SKILL.md「执行流程主干」的 step 3/4 按需加载。本文件给**每类页面的骨架**
> 与**必答问题**——回答不了必答问题，说明这页还没到能写的时候，回去读源码或并页。

通用要求（所有页面）：`##`/`###` 语义式标题、无数字前缀；每页 ≥1 张本页主题图；
可枚举内容成表；章末 `> 依据：…` 聚合出处；frontmatter 带 `title` 与 `description`。

---

## 首页 `README.md`

见 [page-plan.md](page-plan.md)「首页 README 骨架」。要点：它是**入口**，不是概览正文。

必答：这是什么（三句内）？有哪些页？按什么顺序读？**不做什么**？

## `overview.md` —— 项目概览

```
## 一句话定位
## 解决什么问题            <- 讲痛点，不讲功能。读者要能对号入座
## 给谁用 / 典型场景         <- 场景表
## 核心能力一览             <- 能力 | 说明 | 典型场景
## 技术栈                   <- 组件 | 用途 | 选型理由
## 与同类项目的差异          <- 对比表（可省）
## 现状与边界               <- 不做什么、限制、未完成项
```

必答：它替代了谁的什么工作？**为什么不用现成方案**？不适用在什么场景？
技术栈里每个关键组件的选型代价是什么？

## `architecture.md` —— 系统架构

```
## 整体形态            <- 一张结构图打头，配一段导读
## 分层与职责          <- 每层一段：负责什么、不负责什么
## 模块地图            <- 目录/模块 | 职责 | 关键概念
## 主链路              <- 时序图或流程图，从入口到落库/返回
## 关键设计取舍         <- 每条：选了什么、没选什么、代价
```

必答：系统的边界在哪？请求从进来到出去经过哪些环节？
**哪一层承担了最关键的复杂度**，为什么放在那里？

## `<feature>.md` —— 能力/特性页

```
## 这个能力解决什么
## 怎么用                <- 用法表 / 命令 / 配置，配最小可用示例（不放长代码）
## 内部怎么运转          <- 流程图；讲清关键阶段与状态
## 边界与限制            <- 什么情况下不work、有什么前提
```

必答：用户怎么感知到这个能力？它的输入输出边界是什么？
**在哪一步最容易出错**、项目怎么处理？

## `data-model.md` —— 数据模型

```
## 数据全貌            <- ER 图或实体关系图
## 实体与字段           <- 每个核心实体一张字段表：字段 | 类型 | 约束 | 说明
## 数据怎么流转         <- 写入路径 / 读取路径，各一张图或一段
## 生命周期与归档        <- 数据怎么产生、怎么过期、怎么清理
## 演进方式            <- 加字段/迁移怎么做，兼容性怎么保证
```

必答：**为什么用这种存储**（关系型 / 文档型 / KV / 时序）？
哪些字段是设计的核心、哪些只是实现细节？数据量增长后第一个瓶颈在哪？

## `deployment.md` —— 部署与运行

```
## 部署形态            <- 一张部署图
## 前置依赖            <- 依赖 | 版本 | 用途
## 配置项              <- 配置 | 类型 | 默认值 | 说明（表）
## 启动与验证          <- 步骤化，可用命令与预期输出（短）
## 运维要点            <- 日志在哪、怎么观测、常见故障与处置
## 升级与回滚
```

必答：最小可跑起来需要哪些东西？**生产环境与开发环境差在哪**？
出问题时第一个该看什么？

## `concepts.md` —— 核心概念模型（库/SDK/框架、智能体类项目适用）

```
## 概念地图            <- 一张概念关系图，这是本页主体
## 逐个概念解释         <- 概念 | 一句话定义 | 在系统里的角色
## 概念之间怎么组合      <- 组合方式 / 生命周期
```

必答：读者要理解这个项目，**必须先建立哪几个概念**？
这些概念在别处叫什么（帮助读者迁移已有认知）？

## `api-design.md` / `extension.md` / `configuration.md`

| 页面 | 骨架要点 | 必答 |
|------|---------|------|
| `api-design.md` | 接口总表 → 按场景分组详解 → 错误约定 | 接口的设计哲学是什么（REST 资源化？RPC 命令式？）；一致性如何保证 |
| `extension.md` | 扩展点总表 → 每个扩展点怎么接 → 最小插件示例 → 生命周期 | 在哪一层扩展；扩展的代价与限制是什么 |
| `configuration.md` | 配置分组表 → 关键配置详解 → 配置优先级与来源 | 配置从哪来（文件/环境变量/远端）；冲突时谁赢 |

## 单页自检

- [ ] frontmatter 有 `title` 与 `description`（description 面向检索，含项目与主题关键词）
- [ ] 标题为语义式，无数字前缀
- [ ] 必答问题全部能回答（答不了 → 这页该并或该删）
- [ ] ≥1 张本页主题图，且图有导读与着落
- [ ] 可枚举内容已成表
- [ ] 代码在预算内，或已写 `<!-- code-budget: 理由 -->`
- [ ] 章末依据行的路径与行号真实（由 `scripts/check-all.mjs` 校验）
- [ ] 没有"可能/大概"类含糊表述；没有把未完成项写成设计选择
