# Handoff

把当前会话压缩成**一段给新会话用的文本指令**。只打印，不落盘。

## 铁律

1. **零副作用**：不写文件、不建目录、不改配置、不 `git add/commit`。唯一动作是在聊天里输出一个代码块。
2. **一个代码块**：整段交给用户复制；块外只允许一句收尾提示。
3. **≤80 行**：超了删细节、保结论；宁短勿全。
4. **不抄对话、不贴代码**：只写结论 + `path:line` 锚点；不写密钥、token、隐私。
5. **可核对**：每条现状/已完成都要有锚点或命令结果；取不到证据的标 `[待核实]`。

## 意图路由

| 意图 | 信号 | 动作 |
|---|---|---|
| `print` | "交接""续跑提示""换个会话继续""把进度总结给下一个会话" | 按下方流程生成并打印 |
| 恢复 | "继续上次交接""按这份交接继续" | 不归本 skill：让用户把交接文本粘贴进来，再按文本执行；不要凭空重建上下文 |

## 参数

可选「任务范围」。为空时交接当前/最近一个任务；对话里有多个任务先问用户交接哪个。

## 流程

1. **定边界**：从对话里提炼原始需求、验收标准、范围边界；确认交接的是哪一个任务。
2. **取证**（只读，不修改任何东西）：
   - `git rev-parse --abbrev-ref HEAD`、`git status --porcelain`、`git log --oneline -5`、`git diff --stat`
   - 抽查「关键位置」里的文件与行号是否仍有效
3. **压缩**：读 `references/template.md`，按固定小节写；先写「下一步」，再回填已完成与决策。
4. **打印**：输出一个 Markdown 代码块（围栏用三个反引号，语言标 `markdown`），块外只写一句「复制上面整段到新会话即可；有进展后再跑一次 `/handoff` 刷新交接。」
5. **自检**：逐条过下面的清单，不过就改。

## 自检

- [ ] 只有**一个**代码块，首段就是给新会话的核对 + 续跑指令
- [ ] 小节按模板顺序；没有内容的小节已删（不留 N/A）
- [ ] ≤80 行
- [ ] 每条已完成/现状都有 `path:line` 或命令结果
- [ ] 「下一步」第 1 条具体到文件/函数/命令，可直接开工
- [ ] 没有密钥、token、隐私，没有大段代码
- [ ] 没有写任何文件（`git status` 与执行前一致）

## 不做

- 不生成 `.dsh/handoff/*.md`（用户明确只要打印）。
- 不提供 `/handoff/resume`；恢复靠用户粘贴文本。
- 不替用户执行「下一步」。
