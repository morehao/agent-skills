# 交接输出模板

## 骨架

以 Markdown 代码块输出，严格按下面顺序；没有内容的小节整节删掉。

```text
你在继续一个已有任务。先核对当前仓库状态（分支、工作区、下面「关键位置」里的文件是否仍存在），
与交接不一致就先报告差异、不要直接开干；然后从「下一步」第 1 条继续。
不要重做「已完成」，不要重开「关键决策」。

## 任务
<一句话 + 原始需求要点，2–4 行>

## 目标与验收
- <可验证的验收 1>
- <可验证的验收 2>
- 范围边界：<不做什么>

## 当前状态
- 分支：<branch> ｜ HEAD：<short sha>
- 工作区：<干净 / 改动的路径清单>
- 已验证：<命令 → 结果>

## 已完成
- <结论>（`path:line`）

## 下一步
1. <具体动作：文件/函数/命令>
2. <...>

## 关键决策（勿重开）
- <决策> → 理由：<...>；否决：<...>

## 关键位置
- `path:line` — <作用>

## 未决问题
- <需用户拍板 / 已知坑>
```

## 每节写什么、不写什么

| 小节 | 写 | 不写 |
|---|---|---|
| 任务 | 用户原始诉求、要解决什么 | 寒暄、过程叙述 |
| 目标与验收 | 可验证的完成标准、范围边界 | 无法验证的形容词（"更好用"） |
| 当前状态 | 分支、HEAD、改动路径、已跑过的验证 | 完整 diff、全部 `git status` 输出 |
| 已完成 | 每条「结论 + 锚点」 | 贴代码、逐轮回放对话 |
| 下一步 | 有序、可执行，第 1 条能直接开工 | "继续完善"这类空话 |
| 关键决策 | 决策 + 理由 + 被否决方案 | 尚未拍板的选项（放「未决问题」） |
| 关键位置 | 新会话必须打开的文件/行 | 无关文件清单 |
| 未决问题 | 需用户拍板、踩过的坑、无效尝试 | 已解决的问题 |

## 正例 / 反例

正例：

- `已把注入指令里写死的 git-kit 改成读 def.skill（commands-dsh/lib/index.js:103-111）` —— 结论 + 锚点，新会话可直接核对。
- `下一步：在 skills/handoff/SKILL.md 的意图路由表里补 print 分支的验收条目` —— 具体到文件与小节。

反例：

- `改了一些命令相关的东西` —— 无锚点，无法核对。
- 贴 30 行 diff —— 超预算，新会话不需要。
- `下一步：继续完成剩余工作` —— 不可执行。

## 长度控制

- 目标 50–70 行，硬上限 80 行。
- 超限先删「已完成」里的过程描述，再删「关键决策」里的次要项；「任务」「下一步」「关键位置」不删。
