# 技能说明

`skills/` 下的技能同时供 opencode 与 dsh 使用。每个技能一个目录：`SKILL.md` 是入口（frontmatter 的 `description` 决定何时触发），复杂逻辑按需拆到 `references/`，可程序化执行的校验/操作放在 `scripts/`。

`skills/` 下只放技能目录，不放说明文件——接入脚本和 dsh 都按目录扫描。

## git-kit

Git 工作流的唯一真源。`SKILL.md` 只做意图路由：先判断命中哪个分支，再按需加载 `references/<branch>.md`。

| 分支 | 用途 |
|---|---|
| `commit-message` | 只生成 commit message，不提交 |
| `commit-push` | 生成 message + 提交推送；起点是稳定分支时自动建工作分支 |
| `branch` | 按中文描述建候选分支并切换 |
| `pr-create` | 创建/更新 PR/MR（自动识别 gh/glab） |
| `pr-merge` | 合并 PR/MR、删 head（稳定分支保留）、回主干更新 |
| `tag` | 打注记 tag 并推送 |
| `checkout-tag` | 切换到当前仓库的最新 tag（只切不改，默认 detached HEAD） |
| `release` | `pr-merge` 之后的发布段：预检 → 打 tag → 默认建 Release → 校验后效 |
| `slim` | 仓库瘦身为浅克隆 |
| `star-classify` | 拉取并分类 GitHub star |

`references/` 里另有跨分支共用的 `stable-branch.md`（稳定分支唯一定义）、`repo-id.md`（gh/glab 仓库参数）、`commit-format.md`、`ask-options.md`、`version-conventions.md`。完整流程见 [git-kit 工作流](git-kit.md)。

三个入口——opencode `/git/*`、dsh `/git-*`、自然语言——共用这套实现；命令只保留意图声明，不重复逻辑。

## handoff

单文件技能（只有 `SKILL.md`）。把当前会话压成一段可直接粘贴给新会话的续跑提示：

- 只打印一个 Markdown 代码块，不落盘、不改仓库；
- 每条结论带 `path:line` 或命令结果；取不到证据标 `[待核实]`，没跑过标 `[未验证]`，决策没落点标 `[未落盘]`；
- 模型可见、可自行触发：`description` 里写明触发语（「交接一下」「生成续跑提示」「handoff」、换工具/换目录/交给别人）；与斜杠入口 `/handoff` 等价，不要求用户手动敲命令。

入口：opencode `/handoff`、dsh `/handoff`。

## project-insight

开源项目深度解读：解构边界、模块责任、关键链路与设计决策，产物落进知识库仓库（README + 关注面子文档）。

- **先定基线**：`select-baseline.mjs` 按稳定 tag > 稳定分支 > 默认分支程序化选定，写作/校验同一棵树，基线写进产物；
- **叙述优先、引用按需**：正文写设计判断与权衡；代码引用只给反直觉结论、具体数字、安全边界、用户指定核验这几类关键论断，整篇零引用合法；
- **凡引用必验**：落盘的 `文件:行号` 经 `verify-references.mjs` 重定位（首末行锚点），`--stats` 可查密度（只报告不阻断），失败标 `[UNVERIFIED]`；
- **图与表承载过程**：启动流程/请求链路用 Mermaid 或 SVG（走 `diagram-design`），落盘前 `check-mermaid.mjs` 真解析、SVG 跑边拓扑审计；
- **类型规格补关注面**：数据模型 / 部署 / 智能体 / 框架等由类型判据触发，子文档按关注面拆分；
- 增量模式以 `git diff` / release notes 为唯一依据，维护独立 `CHANGELOG.md`；落盘后不做 `git add/commit`。

适合：想从项目里学架构设计、要设计判断与可迁移模式的开发者。

## project-wiki

面向**不读源码的读者**写项目 Wiki（Markdown + Mermaid，可选 `assets/*.svg`）：

- 表达手段按读者成本排序：散文 → 图 → 表 → 代码；
- 出处收进章末一行 `> 依据：`（用 code span，不写可点击链接）；正文不出现校验痕迹（锚点指纹、`Sources:`）；
- 代码预算：非图表代码块每页 ≤3 块、单块 ≤15 行、单页 ≤40 行，超了写 `<!-- code-budget: 理由 -->` 显式豁免；
- 真实性由作者侧门禁 `scripts/check-all.mjs` 保证（代码预算、依据行、首页索引、图表复杂度、版本契约等），Mermaid / SVG 校验复用 project-insight 引擎；
- 单基线契约：校验根与 `--expect-baseline` 必须一起交，快照只对自述的那个基线成立。

适合：给团队一份能读的文档。与 `project-insight` 的分工是**产出性质不同**：要学架构设计、要决策与可迁移模式走前者；要一份不读源码也能读的系统说明走后者。

## tech-design

技术方案 / 技术设计文档。先定**范围**再定组织：一份方案里只有 1–3 处真正需要设计，先找出这几个**挑战点**（约束冲突 / 数量级跨越 / 所有权不清 / 失败不可逆，命中任一才算），由它决定这一版做什么、取证看什么；其余是标准做法，一句带过。范围确定后再用三轴决定文档怎么组织：

- **档位**（轻量 / 标准 / 完整）定篇幅与时间盒（30 分钟 / 半天到两天 / 一周以上）；
- **场景**（新建 / 增量改造 / 结构重构 / 替换迁移 / 下线废弃 / 专项优化，单选）定过程义务；
- **专题**（架构 / API / 数据模型 / 性能容量 / 安全 / 迁移手法，可多选）定技术加固点，只加深挑战点与硬约束落在的那几节。

先答「落点」第 0 问（新系统 / 既有系统的新模块 / 既有系统的既有模块），再找出 1–3 个挑战点，然后按落点与挑战点取证，最后按叙事链 10 问推理成文——**取证先于动笔**。六条硬要求：

- **挑战点优先**：1–3 个真难点 + 各自取舍，其余标「标准做法」不展开；写不出挑战点说明这份文档不该写；
- **事实有据**：既有系统的现状、影响面、调用方、容量水位带 `路径:行号`、监控口径或工单号；取不到标 `[待核实]`；
- **量化义务**：性能、容量、可用性、成本、收益给数字 + 口径 + 假设；
- **取舍对偶**：每个选型写代价与不该选的场景，并回指目标；
- **宁轻勿重**：不适用章节删掉，不留 N/A；完整档必备章节确不适用写 `章节豁免：<理由>`；
- **图是论证**：结构/边界/流转/关系必须有图；下限为轻量档（有结构类章节即须有图）0 张起、标准 ≥2、完整 ≥3，确不适用写 `图豁免：<理由>`。

交付前过三道闸：作者自检 → 文档门禁 `check-design-doc.mjs`（占位符/空壳章节/状态块/备选/追溯表/DDL 一致性/**挑战点缺失或超量**/**追溯表「挑战点」列与承接**/**按章节缺图与档位最小图集**/章节豁免，三档严重度）→ 评审 gate（完整档必跑，第 2 段先复核挑战点是否收敛，再独立上下文 + 并行 lens，只回 `VERDICT` 与 top3）。

**迁移提示**：标准/完整档存量文档要过新门禁，需补「挑战点与取舍」节（编号 C1…Cn）、追溯表「挑战点」列与承接关系；轻量档一句话即可，不编号。

配图 Mermaid 与 SVG 均为一等公民，**先图后文**（先填视图清单，再写正文）；`check-mermaid.mjs` / `audit-svg-topology.mjs` / `render-svg-preview.mjs` 是 project-insight 引擎的薄壳。

## tech-design-research

**调研驱动**的技术设计文档：先调研同类热门开源实现（读源码取证），再用 `tech-design` 的骨架写第一版，**调研结果是第一版的输入**，不是写完再补。

- **不重复 tech-design**：骨架、挑战点判定、档位/场景/专题、六条硬要求、`check-design-doc.mjs`、评审 gate 的 lens 定义全部以 `tech-design` 为真源；本技能只管串接顺序与三段增强。
- **流程顺序**：定课题/档位/**输出落点** → **开工确认（选项式）** → **开源调研（前置）** → 带参照系写第一版 → 按终局做取舍 → 评审门禁闭环 → 命名收尾。
- **开工确认**：基调（默认终局）、档位（默认完整）、评审深度、交付动作、取舍拍板权——**每项都给推荐**（推荐排第一标「（推荐）」），用选项一次问清；不回答按默认值并在报告点明。**调研是默认行为**，用户点名了某开源项目则额外追加调研该项目（不替代默认调研）。
- **开源调研**（核心，`references/oss-research.md`）：读 README 出「业界 vs 本方案」横向表 → `git clone --depth 1` 读源码取证关键论断 → 横向表作为第一版输入；每条借鉴回指文档哪节/哪个决策/采纳与否。用完清理临时目录，不抄 AGPL/GPL 代码。
- **按终局做取舍**：不可逆结构决定（唯一键、分片键、状态机枚举）即使当期不用也定死并写「不改的代价」（如唯一键带 `domain_id`）。
- **输出落点**（`references/delivery.md`）：**先探测环境、给选项让用户选一次**；Obsidian 存在时优先，并把库内最贴合的具体路径直接写进选项（不自动落、不擅自定）。
- **命名规则**：技术设计文档一律 `<主题>-<类型>.md`（连字符切主题|类型，如 `短链-系统设计.md`）；改名同步 wikilink。
- **闭环验收**：门禁 `--strict` 到 0 error/0 warn、Mermaid 与 SVG 校验通过、独立上下文 1–2 个 lens 收成单一 `VERDICT`，改完重跑门禁。

适合：练习经典系统设计题（短链、秒杀、IM、Feed…）并对照主流开源实现、确保「合理且符合主流」。只写方案不需调研走 `tech-design`。

## resume-griller

面试官视角：读候选人简历，产出**能带进面试的 Markdown 手册**。方向与「改简历」「模拟面试陪练」相反——前者帮你招人，后者帮你去面试，别混。

- **无源不出题**：每题挂 `题源：「简历原文」— 项目 · 段落`；引不出原文的疑点移到「必须核实」，不伪装成项目题；
- **答案不编事实**：示范答案里的数字、职责、时间线只能用简历或面试官给的信息，缺口写 `〔待补充：…〕`、假设写 `〔假设：…〕`，两者都只记 note；
- **只问判断**：原则、取舍、失败归因、可证伪的评估、迁移推演；命令参数复述与八股不单独成题；
- **覆盖逐项交代**：技能栏有、项目里无的技能至少追一题，不问的写 `覆盖豁免：<理由>`；
- **时间预算是硬约束**：每题标分钟数与 `优先级：必问 / 选问`，合计不得超过面试时长；「面试前」给一行 `短版`，说明 40 分钟只问哪几题；超了按优先级删题，不压开场收尾；
- **评分靠锚点**：维度按 4/3/2/1 打分并各附一句依据，判定按固定优先级（任一维 1 或未解释的事实矛盾 → 不通过；任一维 2 → 待定；均分 ≥3.0 → 通过）；★ 必须落在 `level` 对应档位（初级/中级 3、高级/架构 4），面评草稿必须回指题号。

结构由 `scripts/check-interview-doc.mjs` 机械校验（元数据块与 `level`、四个段落、题源引用、★ 档位、优先级与短版、时长预算与时间表对账、覆盖表引用、未收口记号、围栏内示例不计入）；题源是否真在简历里由 `scripts/verify-sources.mjs --resume <清洗稿>` 单独核（归一化包含 + 水印容差 + 数字守卫）；题目深度与答案质量由 `references/question-design.md` 末节的自检清单兜底——**门禁判自洽，不判好坏**。

入口：自然语言（「根据这份简历出面试题」「帮我准备面试」）。

## diagram-design（外部）

图由上游技能 [`diagram-design`](https://github.com/cathrynlavery/diagram-design) 产出：45 种图型（架构 / 时序 / 状态机 / 桑基 / 瀑布 / 箱线 / 沃德利…），先把图画成自包含 HTML + 内联 SVG，再用它自带的 `scripts/export_svg.py` 导出成 `.svg` 落进文档。**本仓不 vendor、不改它**，按上游方式自行安装；本仓只规定「用哪张图、落地到哪、怎么验收」。

选它之前先认三条实测边界（本仓门禁的结论，不是它的缺陷）：

- 导出必须带 `--system-fonts`。默认导出内联 Google Fonts `@import`，会命中 `scan-narrative` 的 `[SVG-EXTERNAL]`；带上之后字体退回系统字族，「编辑感」主要剩版式与连线纪律。
- 产物没有 `class="node"/"edge"` 钩子，`audit-svg-topology.mjs` 会自动改走**几何推断**（含文本的矩形当节点、带 marker 且贴节点的线当连线，图例示例箭头按装饰忽略），输出标注「推断模式」；解析不到节点会报 `[EDGE-UNPARSED]` 并退出 1，不会空跑判通过。
- 产物没有 `:root` 变量与 `prefers-color-scheme`（深色是另一份文件），`render-svg-preview.mjs --dark` 对它没有意义——深浅色都在浏览器里看 HTML。

## disk-cleanup

磁盘空间回收与本地数据瘦身。核心分工：**脚本是执行引擎，判断与安全门在 `SKILL.md`**。

- 一条流程不分叉：只读测量 → 分类报告 → **用户勾选最终清理项** → 只跑勾选项 → 前后对比复核；
- macOS 磁盘（`scripts/mac_cleanup.sh`，查询 / `--list` / `--top [N]` / `--clean --dry-run` / `--clean --only <ids>` / `--json` / `--manifest <路径>`）覆盖缓存（`caches`）、日志（`logs`）、临时文件（`tmp`、`varfolders`）、Time Machine 快照（`snapshots`）、开发工具与容器缓存（`xcode`/`xcode-ios`/`node`/`go`/`python`/`rust`/`jvm`/`homebrew`/`cocoapods`/`docker`），以及**项目层**（`projects`：node_modules/构建产物；`dshtmp`：`.dsh/tmp` 过程产物；`projectcache`：Go/pnpm 编译缓存）与**应用内缓存**（`appcache`、`updaters`）、**卸载残留**（`orphans`，只报告、按路径删）；清理项编码是勾选单位，`--only/--skip` 决定这次到底删什么，`--clean` 不带 `--only` 时必须显式 `--all`；
- 预览产出**候选清单**：`--clean --dry-run` 把每条候选路径（编码 / 判定 / 类型 / 路径 / 保护原因）写成 TSV，执行前可逐条核对，`sample_paths` 只作摘要；
- 报告给**两个数字**：目录总量与本次可删量（只删 mtime 阈值的项两者可能差一个数量级），受 TCC 保护的目录单独计数；释放量分两行——各清理项实测可删合计（估算）与 `df` 差值（旁证），不把 `df` 差当清理成果；
- 本地数据库（`scripts/cleanup-opencode.sh`）只是其中一个对象：**用户勾选或点名才处理**，不是每次清理的固定步骤；默认先备份 + `integrity_check` 再事务内删旧会话 + 清孤儿 snapshot + `VACUUM`，`--dry-run` 只统计不落盘；
- 用户数据（聊天记录、浏览器配置、虚拟机镜像、iOS 设备备份、邮件附件）**只报告大小与路径**，不代删，也不进勾选清单；
- agent 执行环境没有 TTY，`sudo` 三类（`/private/tmp`、Time Machine 快照、`/Library` 下的卸载残留）交给用户在自己的终端跑；跑在 `workspace-write` 沙箱里时 `$HOME` 外的删除会被拒（`Operation not permitted`），应改用可写沙箱或同样交用户终端；不可逆操作前先给 `.backup` 备份命令。
- 与 [Mole](https://mole.fit) 的关系：**不接运行时依赖，也不内联其代码与清单**。Mole 面向终端里的人（TUI、广度、GPL-3.0），本技能面向 agent（`--only` 勾选粒度、JSON 契约、自家台账）；两者**白名单与台账互不相认**，同一台机器上别当成一套。取舍理由与后续改造见[决策记录](agents/decisions.md)。

细节见 `references/`（按清理对象分篇：`cleanup.md` 入口通用规则 + `tools/*` 各开发工具 + `macos-system.md`/`project-artifacts.md`/`orphans.md`）。

入口：opencode `/cleanup`（无参数时先给选项）、dsh `/cleanup`（由 dsh-commands 插件提供，语义相同）。

## 怎么选

| 需求 | 技能 |
|---|---|
| 把 Git 流程走完（提交、PR、合并、发版） | `git-kit` |
| 换会话 / 换工具，先把现场交接出去 | `handoff` |
| 从开源项目里学架构设计，要判断与可迁移模式 | `project-insight` |
| 给团队写一份不读源码也能看懂的 Wiki | `project-wiki` |
| 写技术方案 / 设计文档（用户没提调研诉求 → 默认走这个） | `tech-design` |
| 写方案且**明确要求**先调研同类开源实现 / 对标业界 / 符合主流 | `tech-design-research`（窄触发：没提调研诉求不要用） |
| 手里有候选人简历，要出面试题与答案键 | `resume-griller` |
| 只要一张独立图表（45 种图型） | `diagram-design`（外部） |
| 磁盘满了 / 要清缓存与旧会话 | `disk-cleanup` |
